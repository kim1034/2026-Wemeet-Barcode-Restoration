# 난인식 바코드 판독 파이프라인

**METRO팀 · WE-Meet Project 2026**

구겨지고 빛이 반사돼서 스캐너가 못 읽는 바코드를, **기하학적으로 펴서** 읽어내는 프로그램입니다.

AI는 새 픽셀을 만들지 않습니다. **얼마나 휘었는지만 예측**하고, 실제로 펴는 것은 OpenCV가 합니다.

---

## 우리가 푸는 문제

인천세관 통합검사장에서는 컨베이어 위를 지나가는 화물의 바코드를 카메라로 찍어서 읽습니다. 그런데 비닐 포장에 빛이 반사되거나 송장이 구겨져 있으면 못 읽습니다. 그 화물은 **노리드 존**으로 빠집니다.

그러면 이런 일이 벌어집니다.

```
작업자가 화물을 직접 들고 간다
        ↓
구겨진 송장을 손으로 편다
        ↓
공정 맨 앞의 X-ray 라인까지 되돌아가 다시 넣는다
```

**스캔 실패 한 건마다 사람이 공정을 거꾸로 걸어갑니다.** 우리는 이 되돌아가는 과정을 없애려고 합니다.

방법은 하드웨어를 바꾸는 게 아닙니다. 수천만 원짜리 스캐너로 교체하지 않고, **이미 있는 카메라가 찍은 사진을 소프트웨어로 펴서** 읽습니다.

### 우리가 하지 않는 것

"AI가 다 해결한다"고 하지 않습니다. 바코드가 카메라를 향하게 놓는 것은 기존 설비가 합니다. 우리는 **정면을 향하고 있는데도 구겨짐과 반사 때문에 안 읽히는 경우**만 담당합니다.

---

## 어떻게 만드나

사진 한 장이 들어와서 바코드 번호가 나오기까지 4단계를 지나갑니다. 다만 **1단계에서 바로 읽히면 거기서 끝납니다.**

```
  사진 입력
     │
     ▼
 ┌─────────────────────────────┐
 │ 1단계  검출     [AI파트]     │  바코드 부분만 찾아서 잘라낸다
 │                             │  비스듬하면 똑바로 세워서 자른다
 └─────────────────────────────┘
     │
     ▼
   먼저 읽어본다 ──── 읽히면 여기서 끝 (약 0.15초)
     │ 안 읽히면
     ▼
 ┌─────────────────────────────┐
 │ 2단계  기하 추정 [AI파트]    │  얼마나 휘었는지 숫자로 예측한다
 │                             │  이미지를 만들지 않는다
 └─────────────────────────────┘
     │
     ▼
 ┌─────────────────────────────┐
 │ 3단계  기하 보정 [SW파트]    │  OpenCV로 실제로 편다
 │                             │  있는 픽셀을 옮길 뿐이다
 └─────────────────────────────┘
     │
     ▼
 ┌─────────────────────────────┐
 │ 4단계  디코딩   [SW파트]     │  번호로 바꾼다
 │                             │  실패하면 3번까지 다시 펴서 재시도
 └─────────────────────────────┘
     │
     ▼
  펴진 이미지 + 바코드 번호
```

이 4단계를 이어 붙이는 것은 **SW파트**입니다. 그리고 학습에 쓸 데이터를 만드는 것은 **데이터파트**입니다.

### 왜 AI가 이미지를 만들지 않나

생성 모델이 만든 가짜 바코드는 **체크섬을 우연히 통과할 수 있습니다**(Code128 약 1/103). 세관에서 하루 수천 건이면 틀린 번호가 조용히 통과하는 사고가 실제로 납니다. **못 읽는 것보다 나쁩니다** — 못 읽으면 사람이 처리하지만, 틀리게 읽으면 화물이 엉뚱한 곳으로 갑니다.

그래서 AI는 곡률·주름을 숫자로만 내놓고, 변형은 OpenCV가 합니다. 자세한 근거는 [기하 파이프라인 설계](docs/superpowers/specs/2026-08-04-geometry-pipeline-design.md)에 있습니다.

**전체가 0.5초 안에 끝나야 합니다.** 컨베이어가 멈추지 않으니까요.

---

## 전체 흐름 — 데이터 모으기부터 번호가 나오기까지

위 4단계는 **완성된 프로그램이 돌아가는 모습**입니다. 그 전에 **모델을 학습시켜야** 하고, 학습에는 데이터가 필요합니다. 여기서 그 전체 그림을 봅니다.

크게 두 덩어리입니다.

```
[1] 준비 — 9~10월에 하는 일        데이터를 모으고 모델을 학습시킨다
[2] 실행 — 완성된 뒤의 모습         사진 한 장이 번호가 되기까지
```

---

### [1] 준비 — 데이터는 세 종류입니다

가장 헷갈리는 부분이 여기입니다. **"바코드 데이터"가 하나가 아닙니다.** 용도가 다른 세 종류를 각각 다르게 만듭니다.

```
┌─ ① 오픈소스 실사 사진 ────────────────────────────────┐
│  인터넷에서 받아옵니다 (Hugging Face)                    │
│  배경·조명이 있는 진짜 사진                              │
│                                                        │
│  ▶ 어디에 쓰나:  1단계 검출 모델 학습                    │
│  ▶ 정답이 뭔가:  "사진에서 바코드가 여기 있다" 는 상자    │
│  ▶ 왜 필요한가:  복잡한 사진에서 찾는 법을 배워야 하니까   │
└────────────────────────────────────────────────────────┘

┌─ ② 직접 그려서 왜곡시킨 바코드 (합성) ──────────────────┐
│  코드로 만듭니다. 촬영도 라벨링도 필요 없습니다            │
│                                                        │
│  ▶ 어디에 쓰나:  2단계 기하 추정 모델 학습                │
│  ▶ 정답이 뭔가:  "이만큼 휘었다" 는 좌표 24개             │
│  ▶ 왜 필요한가:  정답을 정확히 알 수 있는 유일한 방법      │
└────────────────────────────────────────────────────────┘

┌─ ③ 실촬영 송장 ────────────────────────────────────────┐
│  우리가 직접 찍습니다 (9월 3~4주차)                      │
│                                                        │
│  ▶ 어디에 쓰나:  평가. 학습에는 거의 안 씁니다             │
│  ▶ 정답이 뭔가:  바코드 번호 (평탄 상태로 먼저 찍어서 확보) │
│  ▶ 왜 필요한가:  합성에서 잘 돼도 현장에서 안 되면 의미 없음 │
└────────────────────────────────────────────────────────┘
```

**합성으로 학습하고, 실촬영으로 검증합니다.** 합성에서는 잘 되는데 실촬영에서 안 되면 그게 "도메인 갭"이고, 합성 파라미터를 고치는 근거가 됩니다.

---

### ②의 "직접 그린다"가 무슨 뜻인가

바코드는 **규칙이 정해진 그림**입니다. `8801234567890`을 Code128 규칙에 넣으면 막대 굵기 순서가 하나로 정해집니다. 그걸 그려주는 라이브러리(`python-barcode`)가 있습니다.

```
"WEMEET0001"  →  [python-barcode]  →  깨끗한 바코드 이미지
   우리가 정한 번호                      막대 패턴 그림 (PNG)
```

카메라로 찍는 게 아니라 **인쇄하는 것과 같은 원리**입니다. 이미 우리 테스트가 이 방식을 쓰고 있습니다(`tests/conftest.py`).

이렇게 하는 이유가 세 가지입니다.

| | 이유 |
|---|---|
| **정답 번호를 안다** | 그릴 때 넣은 값이 곧 정답입니다. 실사 사진은 사람이 확인해야 합니다 |
| **픽셀이 깨끗하다** | 오픈소스 데이터는 416px 촬영본이라 이미 흐릿합니다. 흐린 그림에 왜곡을 덧씌우면 "원래 막대가 어디 있었나"가 불분명해집니다 |
| **무한히 만든다** | 번호를 바꿔가며 수만 장을 몇 분에 만듭니다 |

그리고 그린 다음에 **일부러 망가뜨립니다.**

```
① 그린다        "WEMEET0001" → 깨끗한 바코드
② 왜곡시킨다     cv2.remap 으로 원통처럼 감긴 효과 + 주름 + 반사
③ 정답을 계산    ②에서 쓴 왜곡의 "역함수" = 정답 좌표
④ 저장한다      (왜곡된 이미지, 정답 좌표 24개, 정답 번호)
```

**③이 핵심입니다.** 우리가 왜곡을 만들었으니 "어떻게 되돌리면 되는지"를 정확히 압니다. 그게 곧 정답입니다. **라벨링하는 사람이 필요 없습니다.**

---

### 무엇을 학습하는가 — 모델이 두 개입니다

```
┌─────────────────────────────────────────────────────────────┐
│  검출 모델          ①번 데이터로 학습                        │
│                                                             │
│    입력:  사진 한 장                                         │
│    출력:  "바코드가 여기 있고, 12.5도 기울어져 있다"           │
│    정답:  사람이 라벨링한 상자                                │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│  기하 추정 모델      ②번 데이터로 학습                        │
│                                                             │
│    입력:  잘라낸 바코드 이미지        ← 이미지가 들어갑니다     │
│    출력:  좌표 24개                  ← 숫자만 나옵니다        │
│    정답:  합성할 때 쓴 왜곡의 역함수                          │
└─────────────────────────────────────────────────────────────┘
```

**기하 추정 모델은 이미지를 받지만 이미지를 내놓지 않습니다.** "얼마나 휘었나"를 숫자로만 답합니다. 이게 이 프로젝트의 핵심 설계이고, 위 "왜 AI가 이미지를 만들지 않나"에서 설명한 이유입니다.

두 모델은 **따로 학습합니다.** 기하 추정은 합성 데이터만 있으면 되니까 **검출 모델이 완성되기를 기다리지 않아도 됩니다.** 다만 최종적으로는 실제 검출기가 잘라낸 크롭으로 다시 학습·평가해야 정확합니다.

---

### [2] 실행 — 완성된 뒤에 사진 한 장이 들어오면

학습이 끝나면 모델 두 개가 파이프라인에 꽂힙니다.

```
사진 한 장
   │
   ▼
┌──────────────────────────────────────────────────────────┐
│ 1단계  검출 모델이 바코드를 찾아 똑바로 잘라낸다   [AI]      │
│        → 잘라낸 이미지 + 몇 도 돌렸는지                   │
└──────────────────────────────────────────────────────────┘
   │
   ▼
┌──────────────────────────────────────────────────────────┐
│  그냥 한 번 읽어본다                            [SW]      │
│  ─ 읽히면 여기서 끝. 약 0.15초                            │
│    (세로로만 휜 바코드는 안 펴도 읽힙니다 — 실험으로 확인)   │
└──────────────────────────────────────────────────────────┘
   │ 안 읽히면
   ▼
┌──────────────────────────────────────────────────────────┐
│ 2단계  기하 추정 모델이 "이만큼 휘었다"를 숫자로 낸다  [AI]  │
│        → 좌표 24개. 이미지를 만들지 않는다                 │
└──────────────────────────────────────────────────────────┘
   │
   ▼
┌──────────────────────────────────────────────────────────┐
│ 3단계  OpenCV가 그 좌표대로 픽셀을 옮겨 편다      [SW]     │
│        압축된 곳은 늘리고 늘어난 곳은 줄인다                │
│        새 픽셀을 만들지 않는다 — 있는 것만 재배치            │
└──────────────────────────────────────────────────────────┘
   │
   ▼
┌──────────────────────────────────────────────────────────┐
│ 4단계  디코더가 막대 굵기를 읽어 번호로 바꾼다     [SW]     │
│        반사로 날아간 부분은 살아 있는 행만 골라서 씀         │
│        실패하면 다르게 펴서 최대 3회 재시도                 │
└──────────────────────────────────────────────────────────┘
   │
   ▼
바코드 번호 + 펴진 이미지
```

**"디코더"는 AI가 아닙니다.** 막대 굵기 패턴을 읽어서 숫자로 바꿔주는 **기성 라이브러리**입니다(`pyzbar` / `zxing-cpp` / OpenCV 중 하나를 9월에 골라 씁니다). 딥러닝의 encoder-decoder와는 무관합니다.

디코더는 마지막에 **체크섬을 검증**합니다. 이게 우리 설계의 안전장치입니다 — AI가 만든 가짜 바코드가 아니라 원래 있던 픽셀을 옮긴 것이므로, 체크섬을 통과하면 그 번호를 믿을 수 있습니다.

---

### 한 줄 요약

> **깨끗한 바코드를 그려서 일부러 망가뜨려 놓고, "어떻게 망가뜨렸는지"를 맞히는 모델을 학습시킵니다.
> 실제로는 그 모델이 "이만큼 휘었다"고 알려주면 OpenCV가 되돌려 펴고, 디코더가 읽습니다.**

## 시작하기

### 1. 받아오기

```bash
git clone https://github.com/kim1034/2026-Wemeet-Barcode-Restoration.git
cd 2026-Wemeet-Barcode-Restoration
```

### 2. 환경 만들기

[uv](https://docs.astral.sh/uv/)를 먼저 설치하고, 그다음 딱 한 줄입니다.

```bash
uv sync
```

파이썬 버전까지 알아서 맞춰줍니다. `activate` 같은 건 할 필요 없습니다. 파이썬을 돌릴 때는 앞에 `uv run`을 붙이면 됩니다.

```bash
uv run pytest          # 테스트 돌려보기
uv run python -c "import wemeet; print('설치 완료')"
```

### 3. 데이터 받기 — **아직 안 해도 됩니다**

이미지와 모델 파일은 저장소에 없습니다. [Hugging Face](docs/external/huggingface.md)에 두고 명령 하나로 받아올 계획입니다.

```bash
uv run python -m wemeet.data.download   # 아직 만들지 않았습니다
```

**지금은 이 명령이 없습니다.** 받아올 데이터 자체가 아직 없어서(수집은 9월) `download.py` 를 만들지 않았습니다. 2번까지 하면 자기 파트 작업을 시작할 수 있습니다.

## 내 파트는 어디서 시작하나요

**자기 줄의 링크 하나만 열면 됩니다.** 거기에 어떤 파일에서 무엇을 만들어야 하는지 전부 적혀 있습니다.

| 파트 | 담당 | 내 폴더 | 할 일 문서 |
|---|---|---|---|
| **AI** | 김시선, 김대원 | `wemeet/ai/` | **[AI파트가 할 일 →](docs/parts/ai.md)** |
| **SW** | 김종연, 이도훈 | `wemeet/sw/`, `web/` | **[SW파트가 할 일 →](docs/parts/sw.md)** |
| **데이터** | 김강민, 조아라 | `wemeet/data/` | **[데이터파트가 할 일 →](docs/parts/data.md)** |

**무엇부터 해야 하는지는 [파트별 할 일 한눈에](docs/parts/README.md)** 에 순서대로 정리돼 있습니다.

1학년(이다현, 이아침)은 9월 2주차 라벨링 작업부터 시작합니다. [데이터파트 문서](docs/parts/data.md)의 "라벨링" 부분을 보세요.

## 딱 4개만 외우세요

나머지는 필요할 때 찾아보면 됩니다.

| | 내용 |
|---|---|
**명령어 1개** | `uv sync` |
**내 폴더 1개** | `wemeet/ai/` 또는 `wemeet/sw/` 또는 `wemeet/data/` |
**규칙 1개** | AI파트는 `wemeet.sw`를 import하지 않습니다 (어기면 CI가 막아줍니다) |
**조심할 파일 1개** | `wemeet/schemas.py` — 고치기 전에 반드시 상의하세요 |

마지막 줄이 왜 중요한지만 설명하면, `schemas.py`는 **AI파트와 SW파트가 주고받는 데이터의 형식**을 적어둔 파일입니다. 한쪽이 말없이 바꾸면 반대쪽이 전부 깨집니다. 그래서 이 파일은 양쪽 파트 승인이 있어야 머지됩니다.

## 폴더 구조

```
wemeet/                    파이썬 코드는 전부 여기
├── schemas.py             파트 간 약속 (건드리기 전에 상의)
├── ai/                    ← AI파트
├── sw/                    ← SW파트
└── data/                  ← 데이터파트

web/                       React 화면 (SW파트)
downloads/                 받아온 이미지·모델 (저장소에 안 올라감)
tests/                     테스트
docs/                      문서
```

파일 이름이 파이프라인 단계와 그대로 맞습니다. `detection.py`는 1단계, `geometry.py`는 2단계, `rectify.py`는 3단계, `decoding.py`는 4단계입니다.

## 작업 규칙

### 브랜치

`main`에 직접 올리지 않습니다. 항상 브랜치를 만들고 PR을 올립니다.

```bash
git switch -c ai/detection-baseline     # <파트>/<하는일>
```

**이건 규칙이고, 장치로 막아두지 않았습니다.** 마음먹으면 `main`에 바로 push됩니다. 그래서 지켜주셔야 합니다 — 8명이 같은 파일을 건드리는데 PR을 건너뛰면 남이 작업 중인 내용과 충돌합니다.

```
ai/...      AI파트
sw/...      SW파트
data/...    데이터파트
```

### 커밋 메시지

`[파트] 무엇을 했다` 형식입니다.

```
[AI] 검출 모델 학습 스크립트 추가
[SW] 디코딩 재시도 루프 구현
[데이터] 곡률 왜곡 합성 함수 추가
```

### PR

**리뷰어는 올린 사람이 직접 지정합니다.** 오른쪽 `Reviewers`에서 같은 파트원 1명을 고르세요. 위의 파트 표를 보면 누가 어느 파트인지 나옵니다. **승인을 받고 머지하세요** — 승인이 없어도 머지 버튼은 눌립니다.

그리고 자동 검사 3개가 돌아갑니다. **빨간 X여도 머지 버튼은 눌립니다. 누르지 마세요.**

| 검사 | 무엇을 보나 |
|---|---|
| `import-linter` | 파트 간 import 규칙을 어겼는지 |
| `ruff` | 코드 스타일 (자동으로 맞춰줍니다) |
| `pytest` | 테스트가 깨졌는지 |

**빨간 X는 혼내는 게 아닙니다.** 뭐가 잘못됐는지 5분 안에 알려주는 장치입니다. 없으면 2주 뒤에 남이 발견합니다.

각 검사가 실패했을 때 무엇을 하면 되는지는 [CONTRIBUTING.md](CONTRIBUTING.md)에 정리해뒀습니다.
