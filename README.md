# 난인식 바코드 복원 파이프라인

**METRO팀 · WE-Meet Project 2026**

구겨지고 빛이 반사돼서 스캐너가 못 읽는 바코드를, AI로 복원해서 읽어내는 프로그램입니다.

---

## 우리가 푸는 문제

인천세관 통합검사장에서는 컨베이어 위를 지나가는 화물의 바코드를 카메라로 찍어서 읽습니다. 그런데 비닐 포장에 빛이 반사되거나 송장이 구겨져 있으면 못 읽습니다. 그 화물은 **노리드 존**으로 빠집니다.

그러면 이런 일이 벌어집니다.

```
작업자가 화물을 직접 들고 간다
        ↓
구겨진 송장을 손으로 편다
        ↓
공정 맨 앞의 X-ray 라인까지 되돌아가 다시 넣는다
```

**스캔 실패 한 건마다 사람이 공정을 거꾸로 걸어갑니다.** 우리는 이 되돌아가는 과정을 없애려고 합니다.

방법은 하드웨어를 바꾸는 게 아닙니다. 수천만 원짜리 스캐너로 교체하지 않고, **이미 있는 카메라가 찍은 사진을 소프트웨어로 복원**합니다.

### 우리가 하지 않는 것

"AI가 다 해결한다"고 하지 않습니다. 바코드가 카메라를 향하게 놓는 것은 기존 설비가 합니다. 우리는 **정면을 향하고 있는데도 구겨짐과 반사 때문에 안 읽히는 경우**만 담당합니다.

---

## 어떻게 만드나

사진 한 장이 들어와서 바코드 번호가 나오기까지 3단계를 지나갑니다.

```
  사진 입력
     │
     ▼
 ┌─────────────────────────────┐
 │ 1단계  탐지     [AI파트]     │  바코드 부분만 찾아서 잘라낸다
 │                             │  비스듬하면 똑바로 세워서 자른다
 └─────────────────────────────┘
     │
     ▼
 ┌─────────────────────────────┐
 │ 2단계  복원     [AI파트]     │  구겨진 걸 펴고
 │                             │  반사로 날아간 부분을 되살린다
 └─────────────────────────────┘
     │
     ▼
 ┌─────────────────────────────┐
 │ 3단계  디코딩   [SW파트]     │  번호로 바꾼다
 │                             │  실패하면 설정 바꿔서 3번까지 재시도
 └─────────────────────────────┘
     │
     ▼
  복원된 이미지 + 바코드 번호
```

이 3단계를 이어 붙이는 것은 **SW파트**입니다. 그리고 학습에 쓸 데이터를 만드는 것은 **데이터파트**입니다.

**전체가 0.5초 안에 끝나야 합니다.** 컨베이어가 멈추지 않으니까요.

## 시작하기

### 1. 받아오기

```bash
git clone https://github.com/kim1034/2026-Wemeet-Barcode-Restoration.git
cd 2026-Wemeet-Barcode-Restoration
```

### 2. 환경 만들기

[uv](https://docs.astral.sh/uv/)를 먼저 설치하고, 그다음 딱 한 줄입니다.

```bash
uv sync
```

파이썬 버전까지 알아서 맞춰줍니다. `activate` 같은 건 할 필요 없습니다. 파이썬을 돌릴 때는 앞에 `uv run`을 붙이면 됩니다.

```bash
uv run pytest          # 테스트 돌려보기
uv run python -c "import wemeet; print('설치 완료')"
```

### 3. 데이터 받기

```bash
uv run python -m wemeet.data.download
```

이미지와 모델 파일은 저장소에 없습니다. [Hugging Face](docs/external/huggingface.md)에 있고, 위 명령이 `downloads/` 아래로 받아옵니다.

## 내 파트는 어디서 시작하나요

**자기 줄의 링크 하나만 열면 됩니다.** 거기에 어떤 파일에서 무엇을 만들어야 하는지 전부 적혀 있습니다.

| 파트 | 담당 | 내 폴더 | 할 일 문서 |
|---|---|---|---|
| **AI** | 김시선, 김대원 | `wemeet/ai/` | **[AI파트가 할 일 →](docs/parts/ai.md)** |
| **SW** | 김종연, 이도훈 | `wemeet/sw/`, `web/` | **[SW파트가 할 일 →](docs/parts/sw.md)** |
| **데이터** | 김강민, 조아라 | `wemeet/data/` | **[데이터파트가 할 일 →](docs/parts/data.md)** |

1학년(이다현, 이아침)은 9월 2주차 라벨링 작업부터 시작합니다. [데이터파트 문서](docs/parts/data.md)의 "라벨링" 부분을 보세요.

## 딱 4개만 외우세요

나머지는 필요할 때 찾아보면 됩니다.

| | 내용 |
|---|---|
**명령어 1개** | `uv sync` |
**내 폴더 1개** | `wemeet/ai/` 또는 `wemeet/sw/` 또는 `wemeet/data/` |
**규칙 1개** | AI파트는 `wemeet.sw`를 import하지 않습니다 (어기면 CI가 막아줍니다) |
**조심할 파일 1개** | `wemeet/schemas.py` — 고치기 전에 반드시 상의하세요 |

마지막 줄이 왜 중요한지만 설명하면, `schemas.py`는 **AI파트와 SW파트가 주고받는 데이터의 형식**을 적어둔 파일입니다. 한쪽이 말없이 바꾸면 반대쪽이 전부 깨집니다. 그래서 이 파일은 양쪽 파트 승인이 있어야 머지됩니다.

---

## 폴더 구조

```
wemeet/                    파이썬 코드는 전부 여기
├── schemas.py             파트 간 약속 (건드리기 전에 상의)
├── ai/                    ← AI파트
├── sw/                    ← SW파트
└── data/                  ← 데이터파트

web/                       React 화면 (SW파트)
downloads/                 받아온 이미지·모델 (저장소에 안 올라감)
tests/                     테스트
docs/                      문서
```

파일 이름이 파이프라인 단계와 그대로 맞습니다. `detection.py`는 1단계, `restoration.py`는 2단계, `decoding.py`는 3단계입니다.

## 작업 규칙

### 브랜치

`main`에 직접 올리지 않습니다. 항상 브랜치를 만들고 PR을 올립니다.

```bash
git switch -c ai/detection-baseline     # <파트>/<하는일>
```

**이건 규칙이고, 장치로 막아두지 않았습니다.** 마음먹으면 `main`에 바로 push됩니다. 그래서 지켜주셔야 합니다 — 8명이 같은 파일을 건드리는데 PR을 건너뛰면 남이 작업 중인 내용과 충돌합니다.

```
ai/...      AI파트
sw/...      SW파트
data/...    데이터파트
```

### 커밋 메시지

`[파트] 무엇을 했다` 형식입니다.

```
[AI] 탐지 모델 학습 스크립트 추가
[SW] 디코딩 재시도 루프 구현
[데이터] 곡률 왜곡 합성 함수 추가
```

### PR

**리뷰어는 올린 사람이 직접 지정합니다.** 오른쪽 `Reviewers`에서 같은 파트원 1명을 고르세요. 위의 파트 표를 보면 누가 어느 파트인지 나옵니다. **승인을 받고 머지하세요** — 승인이 없어도 머지 버튼은 눌립니다.

그리고 자동 검사 3개가 돌아갑니다. **빨간 X여도 머지 버튼은 눌립니다. 누르지 마세요.**

| 검사 | 무엇을 보나 |
|---|---|
| `import-linter` | 파트 간 import 규칙을 어겼는지 |
| `ruff` | 코드 스타일 (자동으로 맞춰줍니다) |
| `pytest` | 테스트가 깨졌는지 |

**빨간 X는 혼내는 게 아닙니다.** 뭐가 잘못됐는지 5분 안에 알려주는 장치입니다. 없으면 2주 뒤에 남이 발견합니다.

각 검사가 실패했을 때 무엇을 하면 되는지는 [CONTRIBUTING.md](CONTRIBUTING.md)에 정리해뒀습니다.

## 일정

| 시기 | 하는 일 |
|---|---|
| **8월** | 저장소 골격 만들기 — 더미로라도 파이프라인이 끝까지 돌아가게 |
| **9월** | 데이터 만들기 + 1단계 탐지 |
| **10월** | 2단계 복원 + 3단계 연결 + 재시도 루프 |
| **11월** | 화면 + 최종 평가 + 보고서 |

8월에 골격을 먼저 만드는 이유가 있습니다. 각 단계를 **가짜 구현으로 채워서 미리 이어놓으면**, 나중에 진짜 모델이 나왔을 때 가짜를 진짜로 바꿔 넣기만 하면 됩니다. "통합"이라는 힘든 작업 자체가 없어집니다.

## 지금 상태

**골격까지 만들었습니다.** `uv sync` → `uv run pytest` 가 통과하고, 파트 간 import 규칙이 CI로 강제됩니다.

아직 없는 것은 각 단계의 실제 코드입니다.

| 있다 | 없다 (2단계) |
|---|---|
| `wemeet/schemas.py` — 파트 간 계약 | `detection.py` / `restoration.py` / `decoding.py` |
| `tests/` — 계약 검증 + 바코드 픽스처 | `pipeline.py` / `server.py` |
| CI 3검사 (ruff · import-linter · pytest) | `download.py` / `synthesis.py` / `ground_truth.py` |
| [구조와 규칙](docs/architecture.md) | `web/` React 화면 |

위 "데이터 받기"의 `wemeet.data.download` 도 2단계에서 만듭니다. 지금은 받아올 데이터 자체가 없습니다.

파트별 문서에 "무엇을 만들어야 하는지"가 적혀 있으니 그걸 보고 만들면 됩니다.
