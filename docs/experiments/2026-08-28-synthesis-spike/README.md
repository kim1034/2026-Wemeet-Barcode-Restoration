## 설계에 반영할 것

### 고칠 것

| | 내용 |
|---|---|
| **`g = cumsum(m)` → `cumsum(1/m)`** | 설계 §4.1·§8 파이프라인이 방향이 반대입니다. 원통 해석해 대비 오차가 **0.24px 대 35.1px**. `cumsum(m) < x` 라서 "펴진 폭이 관측보다 좁다"는 물리적으로 불가능한 결과가 됩니다 |
| **`np.clip(m, …)` → 기울기 전체 스케일 다운** | m 만 자르면 대응하는 z 가 없어져 음영·반사가 기하와 어긋납니다. 높이장을 도입한 이유를 스스로 부숩니다 |
| **설계 §15-6 폐기** | "src/dst 를 뒤집으면 디코딩이 실패한다"가 **성립하지 않습니다.** 20°~70° 전부 뒤집어도 읽혔습니다. 방향 검증은 디코딩이 아니라 해석해 대조로 해야 합니다 |
| **정반사는 곱이 아니라 더하기** | 곱하면 검은 막대가 절대 안 지워집니다(평균 밝기 0.005). 더하면 지워집니다(0.275, 24%가 덮임). 실제 반사는 막대를 덮으므로 더하기가 맞습니다 |
| **반사는 넓어야 정보를 죽입니다** | 좁은 하이라이트(p=200)는 디코더가 우회합니다. p 하한을 40 근처까지 내려야 합니다 |

### 새로 안 것

**① 제어점 격자는 가로로 늘려야 합니다.** 설계 §7.1 은 세로(n_y=3)를 병목으로 지목했지만,
굽이치는 능선을 λ_y 0.5H~4H 로 흔들어도 n_y=2 에서까지 전부 읽혔습니다.
병목은 가로였습니다 — 나이키스트 `λ ≥ 2W/(n_x−1)` 와 측정이 거의 정확히 맞습니다.

| n_x | 표현 가능 최소 파장 | 측정 |
|---|---|---|
| 4 (기본안) | 0.67 W | 0.50W 실패, 0.75W 성공 |
| 6 | 0.40 W | 0.35W 실패, 0.50W 성공 |

**다만 이 권고의 근거는 아직 약합니다.** 랜덤 분포에서 목표 구간 비율은
n_x = 4 / 6 / 8 에서 14% / 12% / 15% 로 **차이가 없습니다**(N=120, 오차 ±3%p).
짧은 파장 샘플이 드물어서 6×3 의 이득이 안 드러납니다. 6×3 이 값을 하려면
현장에 짧은 파장 주름이 실제로 흔해야 합니다 — **현장 확인 항목**입니다.

**② 설계 §8 실측의 조건은 모듈 폭 5.5px 가 아니었습니다.** §8.1 은 "35° 이상 실패"를
보고했는데 5.5px 에서는 70°까지 보정 없이 읽힙니다. `d_m0 = 2.3px` 에서 정확히 재현되고,
그때 원본 폭이 355px 로 문서가 적은 376×280 과 거의 같습니다.
**§8.4 표와 §4.3 의 0.364 는 5.5px 가정으로 계산된 것이라 실험 조건과 어긋나 있습니다.**

**③ 판독 하한 2px 는 2배 이상 보수적입니다.** 합성만 놓고 보면 0.8px 까지 복원됩니다.
다만 노이즈·블러·반사가 없는 조건이므로 안전 마진으로 남기되 상수가 아니라
**파라미터**로 두고 실촬영 후 조정해야 합니다.

**④ 지배 변수는 각도가 아니라 심볼 하나에 걸리는 픽셀 수입니다.**
Code128 은 심볼(11모듈) 안의 상대 폭 비율로 디코딩합니다. 모듈이 5.5px 면 심볼이 60px 이라
어지간한 왜곡은 심볼 안에서 거의 균일해 비율이 안 깨집니다. 2px 면 심볼이 22px 이라
같은 왜곡이 비율을 무너뜨립니다.

**⑤ 그래서 목표 구간은 해상도가 만듭니다.**
"1차 디코딩 실패 & 정답 제어점으로 보정하면 성공" = Stage 2 가 값을 하는 유일한 구간입니다.

| d_m0 범위 | 원본 폭 | 목표 | 불가 | 1차 성공 |
|---|---|---|---|---|
| **1.6~2.2px** | 260~340px | **12%** (열화 없으면 **18%**) | 40% | 48% |
| 2.0~2.8px | 315~420px | 8% | 10% | 82% |
| 2.8~4.0px | 420~580px | 7% | 18% | 75% |
| 전체 1.6~8.0px | — | 6% | 33% | 61% |

`d_m0` 5.0~8.0px 행은 뺐습니다 — 같은 `d_target` 을 쓰면 상대 압축이 극단이 되어
다른 행과 비교가 안 됩니다.

**열화(블러·노이즈·JPEG)는 목표 구간을 줄입니다.** 18% → 12%. 1차 실패는 늘지만
`remap` 으로 복구되지 않아 "1차 성공"에서 "불가"로 건너뜁니다.

**⑥ 목표 구간은 최소 모듈 폭 2.0~3.2px 의 좁은 띠입니다.** 그 위는 1차가 그냥 읽고,
그 아래는 복원 불가입니다. 열화(블러·JPEG)도 같은 모양의 좁은 창을 갖습니다 —
σ=1.6/JPEG75 에서 목표가 되고 σ=2.2 에서 불가로 넘어갑니다.

**⑦ 행별 정규화는 근사가 아니었습니다.** 압축 프로파일이 y 를 따라 평행이동만 하면
(직선이든 굽은 능선이든) 각 행의 적분값이 같습니다 — 측정 오차 정확히 0.
방향이 다른 성분이 섞인 구김에서만 5.44%(17px) 벌어지고, 그건 보정 결과에서
막대가 세로로 물결치는 것으로 나타나 §8.1 대로 무해합니다.

**⑧ 좌표 정합성은 디코딩으로 검증할 수 없습니다.** 증강 후 제어점을 갱신하지 않아도
회전 20°까지 디코딩이 성공합니다. **펴진 이미지 픽셀 비교**로 재면 회전 2°에서도
평균 오차가 3.4 대 59.5 로 **17배** 갈립니다.

**⑨ 여백은 −2% ~ +15% 로 제한해야 합니다.** 바코드 본체를 잘라먹으면 start/stop 이
사라져 샘플이 무효가 됩니다 — −2% 는 보정 후 성공, −6% 는 실패.
패딩(+15%)은 안전합니다.

**⑩ 밀집 대응장은 `G`(펴진→관측) 방향으로 들고 다녀야 합니다.** 그러면 회전이
저장된 좌표에 아핀을 곱하는 것으로 끝나고, 제어점 좌표를 직접 변환하는 코드가 필요 없습니다.
`F`(관측→펴진) 로 들면 벡터장을 리샘플해야 하고 역문제가 남습니다.
`G` 에서 뽑은 제어점은 기존 `control_points()` 결과와 **차이 0.000000** 으로 일치합니다.

### 확인됨

- **물결 상한 `A/λ ≤ 0.41` 이 정확히 경계.** 0.30 에서 보정 성공(모듈 2.58px),
  0.41 에서 실패(1.99px). 설계 §4.2 원문의 `Σ2πA/λ ≤ 0.636`(= `A/λ ≤ 0.10`)은
  4배 보수적이었다
- **`cos ψ` 보정이 정확하다.** `A` 로 파라미터화했을 때 `max|z_x| = 2πA·cosψ/λ`,
  ψ=0~60° 에서 오차 1e-11
- `m = 1/√(1+z_x²) ≤ 1` — 종이는 늘어나지 않는다
- 기울기 예산이 성분을 하나의 단위로 묶는다 (원통 `tanθ`, 물결 `2πA/λ`, 접힘 `tanα`).
  예산 안에서 뽑은 표본은 넷을 섞어도 보정 후 전부 읽혔다
- 원통 `m = cosθ`, 단독 상한 68.7° (d_m0 = 5.5px)
