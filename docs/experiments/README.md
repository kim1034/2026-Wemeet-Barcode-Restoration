# 실험 기록

측정하고 버린 코드와 그 결과를 남기는 곳입니다. **승격된 코드는 `wemeet/` 에 있습니다.**

여기 있는 것은 "설계를 확정하기 전에 진짜 되는지 재본" 기록입니다.
숫자가 어떤 조건에서 나왔는지가 나중에 반드시 문제가 되기 때문에,
결론만 옮기지 않고 재현 가능한 형태로 함께 둡니다.

|---|---|

- 폴더 이름은 `YYYY-MM-DD-주제`
- `README.md` 에 **결론과 한계**를, `RESULTS.md` 에 **측정표 전문**을

  원문은 지우지 않는다 (`decisions/README.md` 의 원칙)

**모든 새 Stage 2 결과는 [평가 프로토콜 v1](../decisions/0005-평가-지표-체계.md)을
따른다.** ResNet18-C3를 개선 기준선으로 사용하며, 앞선 3-way 백본 비교 계획은
그 당시 설계 이력이다. 아래 정리는 재학습·재평가 결과가 아니라 **기존 기록과

### MobileNet 기존 결과 — 사용자 제공 보고값

**출처 상태:** 2026-09-21 작성된 “Stage 2 MobileNetV3-Small 기하 추정 실험”
보고서를 2026-09-23 사용자가 제공했다. 아래는 그 보고서의 수치를 전사한 것이며
이번 작업에서 실행하거나 원본 JSON으로 검증한 결과가 아니다.
보고서가 언급한 `2026-09-21-stage2-mobilenet/runs/*.json` 경로는
2026-09-26 확인한 main에는 없다. 원자료 확보 후 실제 저장 위치/commit을 연결한다.

평가 집합은 synthetic/v1 target 1,500장. 아래 모든 행은 보고서상 동일한
**GT 출력 캔버스 + 전체 격자 TPS + 디코더**를 사용한 oracle 진단이다.

| 제어점 제공 방식 | 정답 C | 오독 W | 무응답 U | EDR_B (%) | FDR_B (%) | 보고된 2D 오차 mean/P95 (px) |
|---|---:|---:|---:|---:|---:|---|
| GT 48점 | 1,500 | 0 | 0 | 100.00 | 0.00 | 0.000 / 0.000 |
| MobileNet spatial | 1,158 | 9 | 333 | 77.20 | 0.60 | 1.833 / 5.157 |
| MobileNet GAP+FC | 1,091 | 11 | 398 | 72.73 | 0.73 | 1.923 / 5.562 |
| GT 4점 호모그래피 | 620 | 15 | 865 | 41.33 | 1.00 | 7.474 / 28.832 |
| 항등 필드 | 430 | 15 | 1,055 | 28.67 | 1.00 | 27.813 / 65.049 |

- 각 행의 C+W+U는 1,500이다. EDR_B·FDR_B는 보고된 장수에서 계산된다.
- spatial−항등 차이는 **48.53%p**, spatial−GAP 차이는 **4.47%p**다.
  반올림 전 장수로 계산한다. EDR_B를 운영 RR_U나 전체 E2E 성공률로 부르지 않는다.
- spatial의 전처리+forward CPU 1 thread p50/p95는 **6.87/7.15ms**,
  parameter 수는 **572,570**으로 보고됐다. v1 Stage 2는 출력 변환까지 포함하므로 재측정한다.
- report의 학습 split은 27,000/3,000, seed 42, AdamW lr 3e-4, batch 64,
  beta=1/154, 최대 100 epoch다. ResNet 기존 학습 조건과 같지 않다.
- “백본은 같고 head만 다름”이라는 표현에는 주의한다. spatial은 stride 16의
  `features[:9]`, GAP+FC는 stride 32의 전체 features를 사용했다.
  비교에서 backbone family는 같아도 feature depth/stride/channel도 바뀐다.
- “정답 네 모서리보다 35.9%p 높다”는 해당 참조 경로의 관측 차이다.
  이를 국소 변형만의 순수한 인과 효과로 단정하지 않는다.
- 제어점 GT가 완벽하지 않으면 오독 0%가 불가능하다고 결론내리지 않는다.
  같은 오독 ID가 D0와 겹치는지도 미분석이며, 겹침만으로 원인을 확정하지 않는다.

### 1차 통합과 성능 개선 순서

강민의 ResNet 1차 구현을 통합 기준으로 두고, 성능 개선 실험은 같은 입출력
계약과 고정 평가 경로에서 비교한다. 아래는 **계획**이며 성능 향상을 보장하지 않는다.

| 순서 / ID | 작업·변경 요인 | 고정할 것 | 완료 산출물 |
|---|---|---|---|
| **E0 평가 기준 정렬** | v1 평가 코드와 sample 기록 연결 | 기존 가중치·데이터 | 동일 정의 EPE, D0 C/W/U, H/H_U 목록, 경로 설정 |
| **E1 ResNet 기준선** | 기존 `best.pt` 좌표·판독·시간 측정 | model/split/checkpoint | 전체·bucket 결과와 원시 예측, 1차 통합 성적 |
| **E2 학습률** | 고정 lr 대 cosine 감소 | 50 epoch·loss·batch·split·seed | ΔRR_H/FDR_H/EPE/지연 비교 |
| **E3 loss beta** | 0.02 대 1/154 후보 | E1 학습 설정에서 beta만 변경 | 작은 오차 영역 변경의 효과 |
| **E4 축별 loss** | 실패와 x/y 오차 관계 분석 후 가중치 변경 | 한 번에 가중치만 변경, loss 스케일 기록 | 판독 개선과 오독 변화 |
| **E5 데이터 보강** | 검증 실패 유형에 맞춘 학습용 변형 보강 | validation ID·평가 경로 | 실험한 변형과 bucket별 성적 |
| **E6 해상도/특징** | 필요할 때 입력 해상도 또는 feature 변경 | 다른 조건, 각각 별도 실험 | 정확도·시간 비용 비교 |
| **E7 최종 확인** | 채택된 변경 조합, 기준선과 학습 seed 3회 | 동일 split·잠긴 설정 | 새 holdout/실촬영 평가와 보고서 표 |

E2/E3 등 최초 효과 비교는 E1 조건에 대한 단일 변경으로 시작한다.
효과가 확인된 변경을 결합할 때는 별도 run으로 남긴다.
기존 seed 42에 더해 seed 43/44를 돌릴 때 **split도 함께 바꾸지 않는다**.
현 trainer는 seed로 split까지 만들므로, 동일 split manifest를 재사용하는 구현이 먼저 필요하다.

### 원자료를 받은 뒤 채울 것

- ResNet `best.pt`와 실제 `split.json`, checkpoint hash, W&B artifact 버전.
- MobileNet spatial/GAP checkpoint·평가 코드 commit·원본 JSON·sample별 예측.
- 동일 분할/경로에서 두 모델의 좌표 지표를 재집계한 표.
- 1차 통합의 crop·출력 캔버스·TPS 축소·decoder/retry 설정과 hash.
- validation에서 선택한 개선안과 최종 holdout의 잠금 기록.

**보고서 구성:** 문제와 역할 → 문헌 근거·고정 지표 → ResNet 기준선 →
단일 변경 실험 → 채택한 조합 → 1차 통합/실촬영 결과 → 오독·속도·한계.
기존 수치는 위의 별도 이력표에서만 사용하고, 미측정 결과를 예상값으로 채우지 않는다.
