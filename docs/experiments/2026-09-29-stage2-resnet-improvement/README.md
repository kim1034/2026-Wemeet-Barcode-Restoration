# ResNet18-C3 기준선 개선: 문헌 조사와 단계별 실험 계획

- 조사일: 2026-09-28, Asia/Seoul
- 상태: 팀원이 수정하며 사용하는 참고용 실험 제안. 재학습·성능 측정·구현은 수행하지 않았다.
- 공유 갱신일: 2026-09-29. 베이스라인 성능 개선의 실행·설정 선택·결과 기록은 별도 팀원이 담당한다.
- 사용 방법: 담당자는 아래 후보와 순서를 자원·검증 결과에 맞게 수정하고 변경일·이유·결과 링크를 남긴다. 제안된 숫자나 실험 횟수는 의무가 아니다.
- 목적: Stage 2의 48점 좌표 계약을 유지하며 바코드 정답 구제율을 높이고 오독과 지연을 관리한다.
- 평가 기준: [stage2-eval-v1](https://github.com/kim1034/2026-Wemeet-Barcode-Restoration/blob/d05485223f91551773467caea39f8d78dc4b5659/docs/decisions/0005-평가-지표-체계.md). 새 지표를 추가하는 계획이 아니라 그 기준으로 개선안을 비교하는 계획이다.

## 1. 권장 순서

기준선 측정·실패 진단 → 학습률 → loss beta → 효과 있는 변경 조합 → 실패 유형별 데이터 → 조건부 구조 변경 → 반복 검증·1차 통합·최종 평가.

첫 묶음은 50 epoch 학습 5회 이내에서 탐색한다. 후보가 유망할 때 기준선·후보 각각 2개 seed를 추가해 총 9회 이내로 반복 검증한다. 이 횟수에는 데이터·구조 후속 실험은 포함하지 않는다. GPU 시간은 기존 학습 로그로 산정하며 지금 추정값을 성능 근거로 쓰지 않는다.

## 2. 코드에서 확인한 출발점

[기준선 보고서](https://github.com/kim1034/2026-Wemeet-Barcode-Restoration/blob/9dfb47918b40dafc20dbc5a282381bd90f12cdfd/docs/experiments/2026-09-21-stage2-resnet18-c3/README.md)와 [학습 코드](https://github.com/kim1034/2026-Wemeet-Barcode-Restoration/blob/9dfb47918b40dafc20dbc5a282381bd90f12cdfd/scripts/train_geometry.py)를 확인했다.

| 항목 | 확인된 설정 |
|---|---|
| 모델 | ImageNet 사전학습 ResNet18, layer3까지 + spatial head |
| 입력 H×W / 출력 | 160×384 / 정규화 src 좌표 48×2 |
| optimizer | AdamW, lr=1e-4 고정, weight decay=1e-4 |
| loss | Smooth L1, beta=0.02, 정규화 좌표에 적용 |
| 학습 | batch 8, 50 epoch, seed 42 |
| train / validation | 27,024 / 2,976 |
| checkpoint 선택 | 기존 best.pt는 validation loss 최소, epoch 48 |

기존 평균 오차 1.3723px는 v1 EPE가 아니다. 기존 checkpoint를 새 기준으로 먼저 측정해야 한다. 초기 조사는 2026-09-28 공개 코드 기준이다. 이후 [PR #18](https://github.com/kim1034/2026-Wemeet-Barcode-Restoration/pull/18)의 추론 어댑터·평가·게시 스크립트가 main에 병합된 것을 확인했다. 실험의 출발점은 해당 구현 검증과 v1 성적표 재집계다.

### 재학습 전에 확인할 두 가지

1. **split과 학습 seed 분리:** 현재 seed는 데이터 분할에도 사용된다. seed 43/44 실행 전에 동일 split manifest를 읽도록 해야 한다. 그렇지 않으면 초기화 효과와 데이터 차이가 섞인다.
2. **출력의 표현 범위:** [모델 코드](https://github.com/kim1034/2026-Wemeet-Barcode-Restoration/blob/9dfb47918b40dafc20dbc5a282381bd90f12cdfd/wemeet/ai/geometry/model.py)는 `identity + 0.5*tanh(raw)`다. 전체 허용 범위 [-0.5,1.5] 안에서도 각 점은 자기 identity 좌표의 ±0.5 안으로 제한된다. train/validation GT의 범위 초과 비율과 점·bucket 분포를 확인한다. 이는 코드로부터 도출한 점검 항목이며, 실제 범위 초과나 포화는 아직 관측하지 않았다.

범위 초과가 의미 있게 발견되면 GT를 이 범위에 투영했을 때의 원본 픽셀 EPE를 계산해 표현 한계의 하한을 진단한다. 해당 샘플을 평가에서 제외하지 않는다. 범위 조정은 별도 구조 실험으로 기록하고 좌표 계약과 항등 초기화를 보존한다.

### 실험 담당자에게 전달할 구현 점검사항

PR #18의 검토 head `edb57481891f589fdaae39941804b89800291195`에서 다음을 확인했다. 병합 여부와 수정 완료는 별개이므로 실제 실험 commit에서 확인하고 체크한다.

- [ ] 게시 스크립트의 고정 성적(1067/1500, 7/1500)을 해당 checkpoint의 평가 JSON·hash와 연결한다. 미평가 모델에는 성적을 붙이지 않는다.
- [ ] torch/torchvision을 포함한 추론 환경을 재현 가능하게 기록하고 실제 추론 테스트가 skip 없이 실행되는지 확인한다.
- [ ] 명시한 가중치 경로가 없으면 다른 기본 모델로 대체하지 않고 오류를 낸다.
- [ ] `strict_rescue_rate=(ok-first_correct)/n` 대신 샘플별 D0·보정 결과와 H/H_U 분모로 구제율을 계산한다.

PR의 합성 보고값은 정답 1,067/1,500(71.13%), 오독 7/1,500(0.47%)이다. **GT 출력 캔버스 + full-resolution TPS** 조건의 기존 보고값으로 보존하며, 이번 문서 작성에서 재측정한 값이나 실전 E2E 성적으로 사용하지 않는다. [당시 실험 보고서](https://github.com/kim1034/2026-Wemeet-Barcode-Restoration/blob/edb57481891f589fdaae39941804b89800291195/docs/experiments/2026-09-21-stage2-resnet18-c3/README.md)

## 4. 단계 0 — 기준선 성적표와 실패 지도 (기존 E0/E1)

### 실행

- 기존 best.pt, split.json, 데이터 revision, checkpoint hash를 확보한다.
- 동일 저장 crop에서 D0, 항등 필드, ResNet, GT 48점 보정을 비교한다.
- GT 48점도 실전 캔버스 경로와 GT 캔버스 진단 경로를 따로 측정한다. GT가 모든 샘플에서 완벽한 상한이라고 가정하지 않는다.
- validation 전체와 고정 H/H_U에서 C/W/U, RR_H/RR_U, FDR, EPE mean/P95, 지연을 채운다.
- bucket/band, 곡률, blur/반사, crop 여백, 점 위치별로 실패를 나눈다. 실제 메타데이터가 없는 유형은 임의로 라벨을 만들지 않는다.
- 원본 송장·합성 기반 이미지·왜곡 그룹이 분할 간 겹치는지 확인한다. 겹침 때문에 split을 수정하면 새 benchmark 버전에서 기준선과 후보를 모두 다시 학습한다.

### 진단에 따른 분기

| 관측 | 다음 행동 |
|---|---|
| 같은 실전 경로의 GT 좌표는 읽히고 예측 좌표는 실패 | Stage 2 학습·좌표 개선의 우선 후보 |
| GT 좌표도 실패 | 캔버스·보간·디코더·관측 정보 손실을 확인. 모델만의 실패로 단정하지 않음 |
| GT 캔버스에서는 읽히나 실전 캔버스에서는 실패 | Stage 3 출력 크기 경로를 별도 실험으로 분리 |
| 합성은 좋지만 실제 crop에서 실패 | crop/촬영 조건 차이와 데이터 보강 우선 |
| 특정 제어점이 출력 범위에 걸림 | 표현 범위 감사 후 별도 head 범위 실험 |

GT 대비 실패 건수는 모델이 회복할 수 있는 여지를 진단하는 자료이며, 전부 회복 가능한 성능 향상량으로 제시하지 않는다.

## 5. 단계 1 — 첫 학습 실험 5개 (E2/E3와 조합)

모든 실험은 같은 사전학습 초기화 정책에서 새로 시작한다. 기존 best.pt를 일부 실험에서만 이어 학습하지 않는다. split·batch·50 epoch·weight decay·전처리·평가 경로를 고정한다.

| ID | 기준 | 유일하게 바꿀 것 | 설정 |
|---|---|---|---|
| R0 | 기존 학습 조건 | v1 평가·checkpoint 선택 적용 | 고정 lr=1e-4, beta=0.02 |
| R1 | R0 | lr 스케줄 | 1e-4에서 1e-6까지 50 epoch cosine 감소 |
| R2 | R0 | Smooth L1 beta | 0.01 |
| R3 | R0 | Smooth L1 beta | 1/154 ≈ 0.00649 |
| R4 | R0 및 유망 단독 후보 | 검증된 요소 결합 | R1 + R2 또는 R3 중 채택 후보. 둘 다 유망할 때만 실행 |

R1에는 warmup을 동시에 넣지 않는다. 초반 불안정성이 확인되면 warmup 유무를 후속 실험으로 비교한다. lr 최대값·epoch 증가·batch 변경도 별도 요인으로 분리한다.

beta는 정규화 좌표 단위다. Smooth L1의 작은 오차 구간에서 gradient는 `error/beta`이므로 beta 감소는 그 구간의 학습 신호를 바꾼다. beta=0.02의 경계는 원본 crop에서 x축 `0.02*(W-1)`px, y축 `0.02*(H-1)`px다. 두 축의 물리적 의미가 다르다. [PyTorch 2.8 공식 정의](https://docs.pytorch.org/docs/2.8/generated/torch.nn.SmoothL1Loss.html)

1/154는 기존 MobileNet 실험과 연결되는 탐색 후보일 뿐 모든 crop에서 1px를 의미하지 않는다. beta가 다른 run의 loss 숫자를 직접 비교하지 않고 동일 EPE·판독 지표로 비교한다.

### checkpoint 선택

v1대로 validation 실전 crop RR_H 최대 → 동률 FDR_H 최소 → EPE mean 최소 → 이른 epoch를 적용한다. 모든 후보에서 같은 epoch 평가 빈도를 쓴다. 실제 판독 경로가 아직 준비되지 않았다면 EPE로 임시 선택하고 geometry_only_selection으로 표시한다. 통합 후 해당 후보들을 동일 실전 경로에서 확인하며 임시 선택 결과를 최종 판독 최적 모델로 부르지 않는다.

### 진행 기준

- EPE만 감소했다면 좌표 개선으로 기록하고, 구제율 개선 여부는 별도 판정한다.
- 오독 증가 후보는 구제율 증가만으로 자동 채택하지 않는다. 샘플별 정답→오독/무응답→정답 전이를 확인한다.
- 한 seed의 작은 개선은 탐색 결과다. seed 42/43/44의 기준선·후보 비교가 있어야 반복성을 설명할 수 있다.
- R4가 단독 후보보다 좋아지지 않으면 단독 후보를 유지한다. 개선 효과의 단순 합산을 예상하지 않는다.

## 6. 단계 2 — 실패 유형에 맞춘 데이터 (E5)

단계 1의 채택 모델을 부모 실험으로 잠근 뒤, 아래에서 validation 실패와 관련된 유형 하나를 선택한다.

| 실험 | 바꿀 요소 | 검증 포인트 |
|---|---|---|
| D1 crop 불일치 | detector의 여백·중심·각도 오차에 맞춘 학습 crop 변형 | 이미지와 GT 48점을 같은 변환으로 갱신. 잘린 영역은 가시성 기록 |
| D2 촬영 차이 | 확인된 blur 또는 반사/조명 유형 한 가지의 범위·빈도 | 기존 합성에 포함된 효과와 중복 여부, 실제 validation 개선 |
| D3 왜곡 분포 | 곡률·국소 굴곡 등 부족한 유형의 sampling 비중 | 해당 유형과 전체 분포 모두 개선하는지 |

합성 레시피에는 이미 조명·blur·noise·JPEG·회전 등의 항목이 있다. 따라서 “증강 있음/없음”보다 현재 분포에 무엇이 부족한지 확인하는 실험이 필요하다.

train에서 새 샘플을 만들거나 재가중한다. validation 실패 이미지를 그대로 train에 넣지 않는다. 실제 촬영 자료는 원본/송장 단위로 train·validation·최종 test를 분리한다. 유형별 오독·GT 보정 성적도 확인해 모델이 복구할 수 있는 기하 실패와 관측 정보 손실을 구분한다.

데이터 총량·epoch당 표본 수·optimizer step 수를 같게 둔 비교를 먼저 한다. 데이터와 step을 함께 늘리면 별도 계산량 증가 실험으로 기록한다. 후보가 효과 없으면 더 강한 증강을 누적하지 않고 실패 유형 분석으로 돌아간다.

## 7. 단계 3 — 원인에 따라 loss/특징 개선 (E4/E6)

이 단계는 필수 실행 목록이 아니다. 앞 단계 결과가 다음 가설을 지지할 때 한 가지만 진행한다.

| 관측 | 실험 후보 | 비용·주의점 |
|---|---|---|
| x/y 오차와 판독 실패의 민감도가 다름 | 축별 loss 가중치 또는 원본 픽셀 좌표 loss | 우선 축별 작은 좌표 교란을 별도로 넣어 민감도 확인. x 가중치를 무조건 높이지 않음. 가중치 합·loss 스케일 고정; 픽셀 loss의 큰 crop 편향 점검 |
| 가는 바·작은 국소 변형에서 오차가 집중 | 입력 H×W 160×384 → 192×448 한 후보 | 전처리와 GT 계약 유지, p95 재측정. 원래 관측에서 사라진 정보가 되살아나는 것은 아님 |
| 해상도를 늘려도 공간 정보 병목이 남음 | layer2 고해상도 특징과 layer3 결합 | head 변경·채널·연산량 증가를 기록. 해상도 변경과 동시에 실험하지 않음 |
| 좌표 EPE는 좋아지는데 보정 결과가 정체 | 좌표 loss + GT 기준 보정 격자/warp 보조 loss | 미분 가능한 TPS/샘플링 구현과 배포 경로 수치 일치 검증 필요. 디코더 성공/실패를 그대로 역전파할 수 없음 |
| 현재 head의 위치 추정 한계가 확인됨 | DSNT 또는 Wing loss 별도 비교 | DSNT는 범위 확장·좌표계 설계 필요. Wing은 좌표 단위에 맞춘 파라미터 조정 필요. 동시에 도입하지 않음 |

warp 보조 손실은 DewarpNet의 좌표+보정 결과 학습에서 아이디어를 차용한 후속 연구 제안이다. 바코드의 주기적 줄무늬 때문에 raw image similarity만 낮추면 정답 정렬을 보장하기 어렵다. GT 좌표 감독을 유지하고 가능하면 합성 GT 격자/대응관계로 보조 항을 설계한다. 격자를 무조건 매끈하게 만드는 규제는 실제 굴곡까지 지울 수 있어 우선 도입하지 않는다.

현재 단계에서는 ResNet50 교체, 제어점 개수 변경, 생성형 복원 모델 도입은 우선순위를 낮춘다. 첫 통합의 좌표 계약과 추론 비용까지 바꾸므로 기존 기준선의 병목을 확인한 뒤 판단한다.

## 8. 단계 4 — 반복 검증과 최종 확인 (E7)

1. 같은 split에서 기준선과 최종 후보를 seed 42/43/44로 학습한다. RNG·증강 seed도 기록한다.
2. seed별 RR_H/RR_U, 오독, EPE, 평균±표준편차를 보고한다. 같은 표본을 3번 썼다고 평가 N을 3배로 늘리지 않는다.
3. 동일 ID를 짝지은 ΔRR_H bootstrap 구간을 v1대로 계산한다. 그룹이 있으면 그룹 단위로 재표집한다. 구간이 0을 포함하면 우월성 확정으로 표현하지 않는다.
4. 채택 모델의 checkpoint는 사전 고정한 validation 규칙으로 선택한다. test 결과로 seed/checkpoint를 고르지 않는다.
5. 강민의 1차 구현에 checkpoint를 교체하고 저장 crop 실전 경로와 전체 E2E를 각각 측정한다. Stage 1·TPS·디코더·재시도는 같은 버전으로 고정한다.
6. 새 합성 holdout/잠근 실촬영 test는 설정 선택이 끝난 뒤 평가한다. 기존 1,500장은 개발·재현 benchmark로 표시한다.

기존 설계의 Stage 2 p95 150ms, E2E p95 500ms 예산은 v1 조건으로 확인한다. 실제 기계가 다르면 현장 예산 충족으로 일반화하지 않는다. 작은 학습 설정 변경도 최종 후보에서 지연을 재확인한다.

## 9. 역할과 보고서 산출물

- 강민의 1차 구현: 같은 좌표 계약과 고정 실전 평가 경로를 제공하는 통합 기준.
- 별도 성능 개선 담당 팀원의 작업: 기준선 실패 지도, R0~R4 결과, 채택 이유, 고정 조건·설정 차이, 개선 checkpoint·hash·원시 결과를 전달.
- 담당 팀원은 병합된 추론 어댑터로 실험 전 점검을 완료하고 합성 validation 실험·실전 crop 평가를 연결한다. 최종 채택은 판독 경로 확인 뒤 결정한다.
- 이 문서는 인계용 참고자료다. 실제 실행 환경, 담당자, 우선 실험, 설정 변경 이유와 결과 PR 링크는 담당 팀원이 추가한다.

각 표에는 데이터/split hash, 평가 경로, checkpoint와 설정 hash를 붙인다. 전체·H·H_U의 분모를 섞지 않고 seed별 표와 최종 평가 표를 구분한다.

발표 흐름은 “실패 진단 → 가설 → 한 요인 실험 → 오독·속도 포함 채택 → 반복·실촬영 확인”으로 구성한다. 실험이 끝나면 성공하지 않은 가설도 근거와 함께 포트폴리오 회고에 남긴다.
