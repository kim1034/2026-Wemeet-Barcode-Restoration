# 측정표 — Stage 1 탐지 · 2026-09-22

전부 **합성 val 2,000장** 기준이다. 실촬영 검증은 하지 않았다.

## 1. 탐지 성능

Ultralytics `val` 기준. v1 은 2클래스, v2 는 단일 클래스이므로 **채점 기준이 달라
mAP 를 직접 비교할 수 없다.** 공정한 비교는 3절의 「최종 성공률」이다.

| | v1 (2클래스) | v2 (단일 클래스) |
|---|---|---|
| Precision | 0.845 | **0.934** |
| Recall | 0.867 | **0.937** |
| mAP50 | 0.914 | **0.973** |
| mAP50-95 | 0.895 | **0.943** |
| 추론 (ms/장) | 8.3 (A100 MIG 1g) | **4.1** (RTX 4050) |

mAP50-95 가 mAP50 의 97% 다. **찾아낸 바코드는 박스를 거의 픽셀 단위로 맞춘다**는
뜻이고, 크롭 품질이 목적인 Stage 1 에서는 이 값이 mAP50 보다 중요하다.

## 2. 추론 시간 — 110 ms 예산 대비

| 단계 | v2 (RTX 4050) |
|---|---|
| 전처리 | 3.4 ms |
| 추론 | 4.1 ms |
| 후처리 | 4.3 ms |
| **합계** | **약 12 ms** |

예산 110 ms 의 11%. 30 fps 카메라를 실시간으로 처리하고도 남는다.
다만 배포 환경 GPU 가 정해지면 다시 재야 한다.

## 3. 규격 판정까지 포함한 최종 성적 (v2)

`code/eval_ratio.py` — IoU 0.5 이상으로 찾고, 5:3 / 6:4 도 맞혀야 성공으로 친다.

| 지표 | 값 |
|---|---|
| 탐지율 (IoU ≥ 0.5) | 94.2% |
| 평균 IoU | 0.955 |
| 규격 판정 정확도 (탐지된 것 중) | 90.8% |
| **최종 성공률** | **85.5%** |

### 혼동표 (행=정답, 열=판정)

| | 판정 5:3 | 판정 6:4 |
|---|---|---|
| **정답 5:3** | 860 | 82 |
| **정답 6:4** | 92 | 850 |

### 손상 여부별

| 그룹 | 장수 | 탐지율 | 최종 성공률 |
|---|---|---|---|
| 무손상 (index 0–9999) | 1,000 | 약 96% | 약 96% |
| 손상 (index 10000–19999) | 1,000 | 92.7% | 75.3% |

**무손상 그룹은 탐지율과 최종 성공률이 같다** — 찾기만 하면 규격은 100% 맞혔다.
규격 판정 오류 174건은 전부 손상 그룹에서 나왔다.

### 화면 속 막대 영역 크기별 (무손상 그룹)

| 긴 변 | 장수 | 탐지율 |
|---|---|---|
| < 200 px | 281 | 99.6% |
| 200–400 px | 350 | 94.9% |
| 400 px 이상 | 369 | 93.5% |

## 4. 남은 문제와 후속 안

손상 바코드의 규격 판정이 81% 다. 현장 라인에 두 규격이 섞여 들어오므로 그냥 둘 수 없다.

| 안 | 내용 | 비용 |
|---|---|---|
| **A. 애매 구간 이중 크롭** | 판정 비율이 기준선(1.583) ± 폭 안이면 두 규격으로 모두 크롭해 디코딩 성공한 쪽을 채택 | 재학습 불필요. 디코딩이 2회 도는 경우 발생 |
| **B. 크롭 기반 소형 분류기** | 크롭 이미지만 보고 5:3 / 6:4 를 판정하는 작은 CNN 추가 | 추가 학습. 예산 몇 ms |
| **C. 프레임 투표** | 30 fps 연속 프레임의 판정을 모아 다수결 | 단일 프레임 API 와 맞지 않음. 파이프라인 계약 변경 필요 |

A 의 효과를 재려면 `code/analyze_ratio.py` 를 돌린다. 틀린 판정이 기준선 근처에
몰려 있으면 A 로 대부분 잡히고, 멀리 흩어져 있으면 B 가 필요하다.
**이 측정은 아직 하지 않았다.**
