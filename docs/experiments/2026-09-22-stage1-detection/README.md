# Stage 1 탐지 — YOLO-OBB 학습 · 2026-09-22

**결론: YOLO11n-OBB 단일 클래스로 학습하고, 5:3 / 6:4 규격은 예측 박스의 모양으로 후처리 판정한다.**
합성 val 2,000장에서 **mAP50 0.973 · mAP50-95 0.943 · 탐지율 94.2% · 추론 4.1 ms**.

측정표 전문은 [RESULTS.md](RESULTS.md)에 있습니다.

## 무엇을 왜 쟀나

`0002` 의 후보 중 **Ultralytics YOLO-OBB** 를 학습해 기준선으로 삼았다.
전통 영상처리 기준선이 아직 없어 직접 비교는 못 했지만, 두 가지를 확인했다.

| 질문 | 답 |
|---|---|
| 회전·구김·반사가 섞인 바코드를 OBB 로 찾을 수 있나 | 찾는다. 탐지율 94.2%, 평균 IoU 0.955 |
| 110 ms 예산 안에 드나 | 든다. 노트북 GPU 에서 4.1 ms (전후처리 포함 약 9 ms) |

## 탐지 대상을 「막대 영역」으로 정의한 이유

흰 종이 라벨 전체가 아니라 **검은 세로 막대들이 모인 직사각형**을 찾는다.
종이 크기는 인쇄 업체마다 다르지만 막대 영역은 규격이 정해져 있어, 비율을
고정할 수 있다. 비율이 고정되면 2단계 기하 추정이 「원래 직사각형이었다」는
사전 지식을 쓸 수 있다.

막대를 송장처럼 짧게 자르지 않고, 막대 영역 자체가 5:3 또는 6:4 가 되도록
길게 그렸다. 모듈 두께를 비율 단위의 배수로만 골라서 픽셀 단위로 정확히
맞췄다 (`code/make_barcode_dataset.py`).

## 2클래스 → 단일 클래스로 바꾼 것이 핵심

처음에는 `barcode_5x3` / `barcode_6x4` 2클래스로 학습했다. 결과가 나빴다.

| | v1 (2클래스) | v2 (단일 클래스 + 후처리 판정) |
|---|---|---|
| Precision / Recall | 0.845 / 0.867 | **0.934 / 0.937** |
| mAP50 / mAP50-95 | 0.914 / 0.895 | **0.973 / 0.943** |

두 규격은 **막대 무늬가 같고 가로세로 비율만 약 10% 다르다.** YOLO 의 분류
갈래는 무늬로 판정하는 구조라 이 차이를 잘 잡지 못했고, 클래스를 틀리면 한쪽에
오탐·다른 쪽에 미탐으로 이중 감점을 받았다.

v2 는 모델에게 「바코드인가」만 묻고, 규격은 **예측 박스의 긴 변 ÷ 짧은 변이
1.583(5/3 과 3/2 의 중간) 이상이면 5:3, 미만이면 6:4** 로 판정한다. 자로 재면
되는 것을 눈대중으로 맞히게 하지 않는다.

## 남은 문제 — 손상된 바코드의 규격 판정

규격 판정까지 포함한 최종 성공률은 **85.5%** 다. 틀린 174건은 **전부 손상
바코드에서 나왔다.**

| | 탐지율 | 최종 성공률 | 규격 판정 |
|---|---|---|---|
| 무손상 (첫 1만 장) | 96% | 96% | **100%** |
| 손상 (두 번째 1만 장) | 92.7% | 75.3% | 81% |

원인은 구조적이다. 찢긴 바코드의 정답 박스는 「원래 막대 영역 전체」인데 모델
눈에는 남은 부분만 보인다. 구김·비틀림·접힘도 겉보기 비율을 바꾼다. **이미지에서
비율 정보 자체가 사라진 경우가 섞여 있다.**

다만 크롭 품질에는 영향이 제한적이다. 비율 보정이 **짧은 쪽만 늘리는** 방식이라
판정이 틀려도 막대가 잘리지 않는다 — 한쪽 여백이 약 10% 더 붙을 뿐이다
(`wemeet/ai/detection/geometry.py::fit_ratio`).

후속 안 3가지는 [RESULTS.md 「애매 구간」](RESULTS.md)에 있다.

## 데이터

합성 20,000장 (train 18,000 / val 2,000), 5:3 · 6:4 각 50%.

| 구분 | 내용 |
|---|---|
| 해상도 | 1920×1080 생성 → 학습용 1280×720 축소 (라벨은 정규화 좌표라 그대로 유효) |
| 구성 | 이미지당 바코드 1개. 흰 종이 없이 **막대와 숫자만** 배경에 직접 합성 |
| 손상 (뒤 1만 장) | 구김·물결·비틀림·각진 접힘·찢김·마모·빛반사·복합 |
| 카메라 | 모션 블러, 초점 흐림, 센서 노이즈, 조명·그림자, 비네팅, JPEG |
| 배경 노이즈 | 종이·도형·인쇄 글씨·낙서·격자·테이프·끈 10~28개 (바코드 영역은 비움) |

**이 데이터는 `wemeet/data` 의 합성 파이프라인과 별개로 만들었다.** `wemeet/data`
는 Stage 2 용 제어점 정답을 내는 것이 목적이고, 여기서는 Stage 1 용 OBB 정답이
필요했다. 두 경로를 합칠지는 `0004` 에서 정한다.

## 재현

```bash
uv pip install ultralytics                 # AGPL-3.0. 필수 의존성에 넣지 않았다
cd docs/experiments/2026-09-22-stage1-detection/code

python make_barcode_dataset.py --out dataset --start 0 --end 20000
python check_dataset.py --data dataset
python shrink_dataset.py --src dataset --dst dataset_720
python train_detection.py --data dataset_720 --model yolo11n-obb.pt \
    --imgsz 960 --batch 8 --epochs 60 --project runs --name barcode_v2
python eval_ratio.py --weights runs/barcode_v2/weights/best.pt --data dataset_720
```

`shear` · `perspective` · `degrees` · `fliplr` · `flipud` 증강은 학습 스크립트에
**0 으로 고정**되어 있다. 박스를 찌그러뜨리는 증강은 5:3 / 6:4 비율을 깬다.
