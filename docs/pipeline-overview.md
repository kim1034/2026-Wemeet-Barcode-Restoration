# 전체 흐름 — 데이터 모으기부터 번호가 나오기까지

**이 문서를 언제 보나**: "데이터를 어디서 구하고, 무엇을 학습하고, 실제로 어떻게 돌아가는지" 전체 그림이 궁금할 때.

- 파이프라인 4단계 요약만 보려면 → [README](../README.md#어떻게-만드나)
- 구조·의존 규칙·시간 예산 → [구조와 규칙](architecture.md)
- 왜 AI가 이미지를 만들지 않는지 → [기하 파이프라인 설계](superpowers/specs/2026-08-04-geometry-pipeline-design.md)
- 내 파트가 무엇부터 할지 → [파트별 할 일](parts/README.md)

---

[README의 4단계 도식](../README.md#어떻게-만드나)은 **완성된 프로그램이 돌아가는 모습**입니다. 그 전에 **모델을 학습시켜야** 하고, 학습에는 데이터가 필요합니다. 여기서 그 전체 그림을 봅니다.

크게 두 덩어리입니다.

```
[1] 준비 — 9~10월에 하는 일        데이터를 모으고 모델을 학습시킨다
[2] 실행 — 완성된 뒤의 모습         사진 한 장이 번호가 되기까지
```

---

### [1] 준비 — 데이터는 세 종류입니다

가장 헷갈리는 부분이 여기입니다. **"바코드 데이터"가 하나가 아닙니다.** 용도가 다른 세 종류를 각각 다르게 만듭니다.

```
┌─ ① 오픈소스 실사 사진 ────────────────────────────────┐
│  인터넷에서 받아옵니다 (Hugging Face)                    │
│  배경·조명이 있는 진짜 사진                              │
│                                                        │
│  ▶ 어디에 쓰나:  1단계 검출 모델 학습                    │
│  ▶ 정답이 뭔가:  "사진에서 바코드가 여기 있다" 는 상자    │
│  ▶ 왜 필요한가:  복잡한 사진에서 찾는 법을 배워야 하니까   │
└────────────────────────────────────────────────────────┘

┌─ ② 직접 그려서 왜곡시킨 바코드 (합성) ──────────────────┐
│  코드로 만듭니다. 촬영도 라벨링도 필요 없습니다            │
│                                                        │
│  ▶ 어디에 쓰나:  2단계 기하 추정 모델 학습                │
│  ▶ 정답이 뭔가:  "이만큼 휘었다" 는 좌표 24개             │
│  ▶ 왜 필요한가:  정답을 정확히 알 수 있는 유일한 방법      │
└────────────────────────────────────────────────────────┘

┌─ ③ 실촬영 송장 ────────────────────────────────────────┐
│  우리가 직접 찍습니다 (9월 3~4주차)                      │
│                                                        │
│  ▶ 어디에 쓰나:  평가. 학습에는 거의 안 씁니다             │
│  ▶ 정답이 뭔가:  바코드 번호 (평탄 상태로 먼저 찍어서 확보) │
│  ▶ 왜 필요한가:  합성에서 잘 돼도 현장에서 안 되면 의미 없음 │
└────────────────────────────────────────────────────────┘
```

**합성으로 학습하고, 실촬영으로 검증합니다.** 합성에서는 잘 되는데 실촬영에서 안 되면 그게 "도메인 갭"이고, 합성 파라미터를 고치는 근거가 됩니다.

---

### ②의 "직접 그린다"가 무슨 뜻인가

바코드는 **규칙이 정해진 그림**입니다. `8801234567890`을 Code128 규칙에 넣으면 막대 굵기 순서가 하나로 정해집니다. 그걸 그려주는 라이브러리(`python-barcode`)가 있습니다.

```
"WEMEET0001"  →  [python-barcode]  →  깨끗한 바코드 이미지
   우리가 정한 번호                      막대 패턴 그림 (PNG)
```

카메라로 찍는 게 아니라 **인쇄하는 것과 같은 원리**입니다. 이미 우리 테스트가 이 방식을 쓰고 있습니다(`tests/conftest.py`).

이렇게 하는 이유가 세 가지입니다.

| | 이유 |
|---|---|
| **정답 번호를 안다** | 그릴 때 넣은 값이 곧 정답입니다. 실사 사진은 사람이 확인해야 합니다 |
| **픽셀이 깨끗하다** | 오픈소스 데이터는 416px 촬영본이라 이미 흐릿합니다. 흐린 그림에 왜곡을 덧씌우면 "원래 막대가 어디 있었나"가 불분명해집니다 |
| **무한히 만든다** | 번호를 바꿔가며 수만 장을 몇 분에 만듭니다 |

그리고 그린 다음에 **일부러 망가뜨립니다.**

```
① 그린다        "WEMEET0001" → 깨끗한 바코드
② 왜곡시킨다     cv2.remap 으로 원통처럼 감긴 효과 + 주름 + 반사
③ 정답을 계산    ②에서 쓴 왜곡의 "역함수" = 정답 좌표
④ 저장한다      (왜곡된 이미지, 정답 좌표 24개, 정답 번호)
```

**③이 핵심입니다.** 우리가 왜곡을 만들었으니 "어떻게 되돌리면 되는지"를 정확히 압니다. 그게 곧 정답입니다. **라벨링하는 사람이 필요 없습니다.**

---

### 무엇을 학습하는가 — 모델이 두 개입니다

```
┌─────────────────────────────────────────────────────────────┐
│  검출 모델          ①번 데이터로 학습                        │
│                                                             │
│    입력:  사진 한 장                                         │
│    출력:  "바코드가 여기 있고, 12.5도 기울어져 있다"           │
│    정답:  사람이 라벨링한 상자                                │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│  기하 추정 모델      ②번 데이터로 학습                        │
│                                                             │
│    입력:  잘라낸 바코드 이미지        ← 이미지가 들어갑니다     │
│    출력:  좌표 24개                  ← 숫자만 나옵니다        │
│    정답:  합성할 때 쓴 왜곡의 역함수                          │
└─────────────────────────────────────────────────────────────┘
```

**기하 추정 모델은 이미지를 받지만 이미지를 내놓지 않습니다.** "얼마나 휘었나"를 숫자로만 답합니다. 이게 이 프로젝트의 핵심 설계입니다. 이유는 [README의 "왜 AI가 이미지를 만들지 않나"](../README.md#왜-ai가-이미지를-만들지-않나)와 [기하 파이프라인 설계 §2](superpowers/specs/2026-08-04-geometry-pipeline-design.md)에 있습니다.

두 모델은 **따로 학습합니다.** 기하 추정은 합성 데이터만 있으면 되니까 **검출 모델이 완성되기를 기다리지 않아도 됩니다.** 다만 최종적으로는 실제 검출기가 잘라낸 크롭으로 다시 학습·평가해야 정확합니다.

---

### [2] 실행 — 완성된 뒤에 사진 한 장이 들어오면

학습이 끝나면 모델 두 개가 파이프라인에 꽂힙니다.

```
사진 한 장
   │
   ▼
┌──────────────────────────────────────────────────────────┐
│ 1단계  검출 모델이 바코드를 찾아 똑바로 잘라낸다   [AI]      │
│        → 잘라낸 이미지 + 몇 도 돌렸는지                   │
└──────────────────────────────────────────────────────────┘
   │
   ▼
┌──────────────────────────────────────────────────────────┐
│  그냥 한 번 읽어본다                            [SW]      │
│  ─ 읽히면 여기서 끝. 약 0.15초                            │
│    (세로로만 휜 바코드는 안 펴도 읽힙니다 — 실험으로 확인)   │
└──────────────────────────────────────────────────────────┘
   │ 안 읽히면
   ▼
┌──────────────────────────────────────────────────────────┐
│ 2단계  기하 추정 모델이 "이만큼 휘었다"를 숫자로 낸다  [AI]  │
│        → 좌표 24개. 이미지를 만들지 않는다                 │
└──────────────────────────────────────────────────────────┘
   │
   ▼
┌──────────────────────────────────────────────────────────┐
│ 3단계  OpenCV가 그 좌표대로 픽셀을 옮겨 편다      [SW]     │
│        압축된 곳은 늘리고 늘어난 곳은 줄인다                │
│        새 픽셀을 만들지 않는다 — 있는 것만 재배치            │
└──────────────────────────────────────────────────────────┘
   │
   ▼
┌──────────────────────────────────────────────────────────┐
│ 4단계  디코더가 막대 굵기를 읽어 번호로 바꾼다     [SW]     │
│        반사로 날아간 부분은 살아 있는 행만 골라서 씀         │
│        실패하면 다르게 펴서 최대 3회 재시도                 │
└──────────────────────────────────────────────────────────┘
   │
   ▼
바코드 번호 + 펴진 이미지
```

**"디코더"는 AI가 아닙니다.** 막대 굵기 패턴을 읽어서 숫자로 바꿔주는 **기성 라이브러리**입니다(`pyzbar` / `zxing-cpp` / OpenCV 중 하나를 9월에 골라 씁니다). 딥러닝의 encoder-decoder와는 무관합니다.

디코더는 마지막에 **체크섬을 검증**합니다. 이게 우리 설계의 안전장치입니다 — AI가 만든 가짜 바코드가 아니라 원래 있던 픽셀을 옮긴 것이므로, 체크섬을 통과하면 그 번호를 믿을 수 있습니다.

---

### 한 줄 요약

> **깨끗한 바코드를 그려서 일부러 망가뜨려 놓고, "어떻게 망가뜨렸는지"를 맞히는 모델을 학습시킵니다.
> 실제로는 그 모델이 "이만큼 휘었다"고 알려주면 OpenCV가 되돌려 펴고, 디코더가 읽습니다.**
