# 2단계(기하 추정) → 3단계(기하 보정) 인계 규격

**누가 읽나**: SW파트 (3단계 · 4단계 담당)
**한 줄로**: **격자점 좌표 두 벌 + 방식 이름 + 신뢰도**, 이 넷만 갑니다. **이미지는 안 갑니다.**

짝이 되는 문서: [1단계 → 2단계 인계 규격](stage1-handoff.md)

```python
GeometryField(
    control_points_dst_norm = ...,   # (N, 2) 펴진 뒤의 격자 위치
    control_points_src_norm = ...,   # (N, 2) 그 내용이 "지금" 있는 위치

```

```python
def estimate_geometry(target: DetectedBarcode) -> GeometryField: ...
#   wemeet/ai/geometry.py  ← 아직 파일이 없습니다
```

## 이미지를 안 보내는 이유

생성 모델이 만든 가짜 바코드는 **체크섬을 우연히 통과합니다** (Code128 약 1/103).
틀린 번호가 조용히 흐르는 것은 못 읽는 것보다 나쁩니다.

그래서 반환형에 **이미지 필드가 아예 없습니다.** 실수로라도 픽셀을 만들어 넘길 수 없습니다.
**펴는 것은 3단계가 OpenCV 로 합니다.**

## 좌표 규약 — 이걸 틀리면 거꾸로 펴집니다

| 항목 | 규칙 |
|---|---|
| 단위 | **0.0 ~ 1.0 정규화**. 픽셀이 아닙니다 |
| 원점 | `0.0` = 첫 픽셀 중심, `1.0` = 마지막 픽셀 중심. **`w−1` 을 곱해서 픽셀로 되돌립니다** |
| 순서 | `(x, y)`. y 는 **아래로** 증가합니다 (이미지 관례) |
| 기준 | `DetectedBarcode.crop_bgr_uint8` 의 **원본 크기**. 모델 입력용 리사이즈 이미지가 아니고, 원본 사진 전체도 아닙니다 |
| 배열 순서 | 행 우선 (위쪽 줄부터, 각 줄은 왼쪽부터) |
| 방향 | `dst` = 펴진 격자, `src` = 지금 있는 위치 |
| `dst` 범위 | `0.0 ~ 1.0` (계약이 검사합니다) |
| `src` 범위 | `−0.5 ~ 1.5` — **크롭 밖을 가리킬 수 있습니다.** 회전 잔차를 2단계가 같이 펴기 때문입니다 |

**정규화라서 리사이즈에 안 어긋납니다.** 실측으로 확인했습니다 — 같은 정규화 제어점으로
192 / 256 / 384 / 512px 로 리사이즈한 이미지를 전부 보정해 판독됐습니다.

### 방향을 뒤집으면 — 디코딩으로는 안 잡힙니다

이게 함정입니다. **뒤집어도 20°~70° 전부 읽힙니다** (제어점 좌표는 정규화 기준
0.008~0.104 만큼 확실히 벌어지는데도). 왜곡을 만들 때 쓴 매핑에서 정답을 뽑으면
라운드트립이 자기일관적이라 그렇습니다.

**설계 §15-6 "뒤집으면 디코딩이 실패한다"는 폐기됐습니다.** 통과하지만 아무것도
검증하지 못합니다. 대신 이 셋을 쓰세요.

| 기준 | 확인 방법 |
|---|---|
| 해석해 대조 | 원통에서 `cumsum(1/m)` 이 `r·arcsin((x−c)/r)` 와 **0.5px 안에서** 일치 (실측 0.24px) |
| 단조성 | 격자 각 줄에서 `src_x` 가 **증가**해야 합니다. 깨졌다면 역보간을 빼먹은 것입니다 |
| 펴진 이미지 비교 | 증강 전후 결과가 픽셀 단위로 일치 (회전 2°에서 오차 3.4 vs 59.5 — 17배로 갈립니다) |

## 3단계가 할 일

```python
def apply_field(
    target: DetectedBarcode,
    field: GeometryField,
    interpolation: int = cv2.INTER_CUBIC,
) -> RectifiedBarcode: ...
#   wemeet/sw/rectify.py  ← 아직 파일이 없습니다
```

```
정규화 좌표 → 픽셀 환산 (w−1, h−1 을 곱함)
          → tps_flow (설계 §9 코드 그대로)
          → cv2.remap(INTER_CUBIC, BORDER_REPLICATE)
          → RectifiedBarcode
```

`method == "perspective"` 면 `cv2.getPerspectiveTransform` + `warpPerspective` 입니다.
**제어점이 정확히 4개일 때만 유효합니다** (계약이 강제하지 않으니 3단계에서 확인하세요).

### 격자 축소 1/4 은 선택이 아니라 필수입니다

`tps_flow` 를 전체 격자로 계산하면 **20ms 예산의 6~12배**가 나옵니다. 1코어 단독 실행 실측:

| 크기 · `n_x` | 전체 격자 | 1/2 | **1/4** | 1/8 |
|---|---|---|---|---|
| 380×280, 4 | 127.9 ms | 17.6 | **3.4** | 1.0 |
| 380×280, 6 | 151.1 ms | 38.6 | **5.2** | 1.3 |
| 784×220, 4 | 176.0 ms | 41.4 | **7.7** | 1.5 |
| 784×220, 6 | 245.7 ms | 66.0 | **13.0** | 4.1 |

1/4 격자로 계산하고 `cv2.resize` 로 늘리면 전부 예산에 들어갑니다.

> **1/4 축소가 보정 품질을 떨어뜨리지 않는지는 아직 안 쟀습니다.**
> 전체 격자와 결과를 비교해 확인해 주세요.
>
> **타이밍은 반드시 단독 실행으로 재세요.** 여러 프로세스를 병렬로 돌리면서 재면
> 같은 조건이 3.4ms → 22.8ms 로 **7배** 부풀려집니다.

## 바코드 실물 규격 (2026-09-07 확인)

쿠팡 로켓배송 라벨 기준입니다. **심볼로지는 Code128.**

| 라벨 | 규격 | A4 |
|---|---|---|
| 아이라벨 540 | 46.9 × 26.902 mm | 40칸 |
| 아이라벨 239 | 62.2 × 30.03 mm | 27칸 |

Code128 은 자릿수에서 모듈 개수가 정해집니다.

```
모듈 개수 = 11 × 자릿수 + 35 + 20(콰이엇 존)
          = 165 (10자리) / 187 (12자리) / 209 (14자리)

모듈 폭(mm) = 바코드 폭(mm) / 모듈 개수
```

| 라벨 | 바코드 폭 (라벨의 75~85%) | 10자리 | 12자리 |
|---|---|---|---|
| 540 | 35.2 ~ 39.9 mm | 0.21 ~ 0.24 mm | 0.19 ~ 0.21 mm |
| 239 | 46.7 ~ 52.9 mm | 0.28 ~ 0.32 mm | 0.25 ~ 0.28 mm |

> **바코드 폭과 자릿수는 추정입니다.** 실물 라벨을 재서 확정해야 합니다.
> `0004` 가 지금 쓰는 0.33mm 는 **낙관적**입니다 — 실제는 0.2~0.3mm 로 보입니다.

### 그래서 카메라가 정해지면 모듈 폭이 정해집니다

```
모듈 폭(px) = 모듈 폭(mm) × 가로 해상도 / 가로 시야 폭(mm)
```

| 카메라 | 시야 폭 | 0.21 mm | 0.24 mm | 0.30 mm | 0.33 mm |
|---|---|---|---|---|---|
| 1920px | 600 mm | **0.67** | **0.77** | **0.96** | 1.06 |
| 1920px | 400 mm | 1.01 | 1.15 | 1.44 | 1.58 |
| 1920px | 300 mm | 1.34 | 1.54 | 1.92 | 2.11 |
| 4K (3840px) | 600 mm | 1.34 | 1.54 | 1.92 | 2.11 |
| 4K | 400 mm | 2.02 | 2.30 | 2.88 | 3.17 |
| 4K | 300 mm | 2.69 | 3.07 | 3.84 | 4.22 |

굵게 표시한 칸은 **복원 불가 영역**입니다 — 합성 실측 하한이 0.8px 입니다.

### 모듈 폭이 2단계의 역할을 정합니다

| 모듈 폭 | 1차에서 읽힘 | 2단계가 값을 하는 비율 | 원리적 불가 |
|---|---|---|---|
| 1.6 ~ 2.2 px | 48% | **12 ~ 18%** | 40% |
| 2.0 ~ 2.8 px | 82% | 8% | 10% |
| 2.8 ~ 4.0 px | 75% | 7% | 18% |
| 5.5 px 이상 | 대부분 | 거의 0 | 거의 0 |

**1920px 로 60cm 를 보면 아무것도 못 읽습니다. 4K 로 30cm 를 보면 2단계가 거의 필요 없습니다.**
그 사이가 이 프로젝트가 값을 하는 구간입니다.

크롭 폭으로 환산하면: `크롭 폭(px) = 모듈 폭(px) × 165` 입니다.
1.54px 이면 크롭이 약 254px, 3.07px 이면 약 507px 입니다.

## 제어점 개수 — 다음 주까지 실험으로 정합니다

지금은 **`6×3 = 18개`(숫자 36개)** 를 쓰기로 하고 진행합니다.
계약은 "최소 4개"만 요구하므로 **`schemas.py` 변경은 없습니다.**

### 가로(`n_x`) — 하한은 확정, 상한은 미측정

제어점이 촘촘할수록 짧은 주름을 표현합니다. `표현 가능 최소 파장 = 2W / (n_x − 1)`.

| `n_x` | 표현 가능한 최소 주름 파장 | 실측 |
|---|---|---|
| 4 | 바코드 폭의 0.67배 | 0.50배 실패, 0.75배 성공 ✓ |
| 6 | 0.40배 | 0.35배 실패, 0.50배 성공 ✓ |
| 8 | 0.29배 | 미측정 |

**상한은 아무도 안 쟀습니다.** 제어점을 늘리면 점 사이 간격이 좁아지고,
간격이 좁으면 같은 좌표 오차가 더 큰 왜곡을 만듭니다.

| `n_x` | 점 사이 간격 (W=376) | 모델에 요구되는 좌표 정확도 (추정) |
|---|---|---|
| 4 | 125 px | ~15 px |
| 6 | 75 px | ~9 px |
| 8 | 54 px | ~6 px |

지금까지의 실험은 전부 **정답 제어점**(오차 0)으로 돌렸습니다. 그래서
"`n_x` 를 늘리면 표현 범위가 넓어진다"만 확인됐고, "실제 모델에서도 나은가"는 미확인입니다.

### 세로(`n_y`) — 근거가 없습니다. 다시 재야 합니다

`n_y` 가 필요한 이유는 세로 변형 때문이 **아닙니다.** 세로로 밀리는 것은 판독을
깨뜨리지 않습니다(설계 §8.1). `n_y` 는 **가로 변형이 높이에 따라 달라지는 것**을
표현하려고 있습니다.

```
주름 능선이 곧고 비스듬함 → 위아래로 위상만 밀림  → n_y = 2 로 표현됨
주름 능선이 굽이침        → 위상이 곡선으로 밀림  → n_y = 3 이상 필요
```

> **"`n_y`=2 로 충분하다"는 근거가 무효입니다.** 유일한 실험(`02_direction.py` 의
> `ridge_sweep`)의 표본 4개가 **보정을 아예 안 해도 전부 읽혔습니다**(`first` 필드가
> 모두 판독 성공). 안 깨진 표본을 흔들었으니 `n_y` 를 뭘 넣어도 읽힙니다.
> 네 행의 `m_min` 이 전부 0.574 로 같은 것도 기울기 예산이 상한으로 잘라낸 결과입니다.

### 다음 주 실험 — 두 개

**① `n_x` × 좌표오차 σ 격자** (모델 불필요, 오늘 가능)

정답 제어점에 인위적으로 가우시안 오차 σ 를 넣고 `n_x` 와 함께 쓸어서 판독률을 재는 것.
설계 §8.3 을 `n_x=6` 한 점에서 격자로 확장하면 됩니다.

- `n_x` ∈ {4, 6, 8, 10}
- σ ∈ {0, 1, 2, 4, 8, 12} px
- 표본은 **목표 구간**(1차 실패 & 정답 제어점으로 보정하면 성공)에서만 뽑을 것

이게 `n_x` 의 상한 곡선을 줍니다. 하한 곡선(나이키스트)과 겹치는 구간이 답입니다.

**② `n_y` 재측정**

실험 08 이 목표 구간 표본을 찾는 방법을 이미 갖고 있습니다. 그 표본으로
`n_y` ∈ {2, 3, 5} 를 흔들면 됩니다. **1차 디코딩이 실패하는 표본만 쓸 것** —
이게 지난 실험이 무효가 된 이유입니다.

### 판정 기준

이진 판독률은 표본이 적으면 차이를 못 잡습니다. 실측으로 `n_x` = 4/6/8 이
14% / 12% / 15% (N=120, ±3%p) 로 **구별되지 않았습니다.** 그래서:

- 표본은 **목표 구간에 집중**시킬 것 (전체에서 뽑으면 75%가 1차 성공이라 차이가 묻힙니다)
- 보조 지표로 **정답 대비 최대 국소 배율 오차**를 같이 기록할 것 (연속값이라 표본이 적어도 됩니다)

### 바꾸는 비용은 쌉니다

합성 데이터가 **이미지가 아니라 레시피로 저장**되므로:

| | 비용 |
|---|---|
| 라벨 재생성 | 레시피에서 다시 뽑으면 됨 (분) |
| 재학습 | 작은 CNN + 합성 데이터 (시간) |
| `schemas.py` | **변경 없음** |
| 실제로 비싼 것 | `0003` 의 후보 비교 표가 무효가 되는 것 |

그래서 지금 `6×3` 으로 진행해도 손해가 작습니다. 다음 주 실험의 값어치는
**`0003` 후보 비교에서 흔들 범위를 좁혀 실험 시간을 아끼는 것**입니다.

## 아직 안 정해진 것

### ① `confidence` 를 어떻게 쓸지 — SW파트가 정해야 합니다 ← 가장 급함

**2단계 v1 은 `confidence` 를 학습하지 않고 상수를 반환합니다.**

그러면 `pipeline.py` 의 이 분기가 죽습니다.

```python
if field.confidence < 0.3:      # 항상 같은 값이 오므로 의미가 없다
    result.degraded = True
    return _fail_with(...)
```

왜 v1 에서 뺐는가 — 정의는 명확해졌습니다(`정답 제어점으로 폈을 때 읽히는가`).
그런데 학습이 안 됩니다.

| | 실측 |
|---|---|
| 왜곡 파라미터 ±1% 에서 라벨 유지율 | **88.3%** (뒤집힌 7건 중 5건이 목표 구간에서 나감) |
| 최소 모듈 폭으로 목표 구간 예측 | 정확도 84.3% — **다수 클래스 기준선도 84.3%** (= 정보 0) |

선택지 셋입니다.

| 선택지 | |
|---|---|
| **항상 보정을 시도한다** | 가장 단순합니다. 그리고 1/4 축소로 보정이 **3.4~5.2ms** 이므로 게이트로 아낄 게 없습니다 |
| 다른 신호를 쓴다 | **포화 화소 비율**이 후보입니다 — 목표 1.49% / 불가 4.35% / 1차성공 1.83%. 반사가 "불가"를 가리킵니다 |
| 상수를 1.0 으로 두고 분기 방치 | 코드는 안 고쳐도 되지만 죽은 코드가 남습니다 |

`degraded` 경로도 같이 걸립니다.

### ② 계약에 남은 구멍 — 세 파트 합의가 필요합니다

| 구멍 | 무슨 사고가 나나 |
|---|---|
| `isinstance(np.ndarray)` 검사가 없음 | **`torch.Tensor` 가 모든 `assert` 를 통과**하고 3단계 numpy 연산 깊은 곳에서 터집니다. 2단계는 torch 로 작업하므로 실제로 일어납니다 |
| `method="perspective"` 에 `N==4` 강제가 없음 | `getPerspectiveTransform` 은 정확히 4점을 요구합니다 |
| 동일선상 4점을 막지 않음 | 아핀 항이 퇴화합니다 |
| **모델 출력의 단조성 검사가 없음** | 학습된 모델이 모순된 제어점을 내면 필드가 접혀 **막대가 복사·소실됩니다.** 합성 데이터 검증(`m > 0`)은 이걸 못 잡습니다 — 합성에서만 참인 성질입니다 |

### ③ 그 외

| 항목 | 상태 |
|---|---|
| 모델 입력 규격 | 제안 **384×96**, 종횡비 깨고 늘림, 흑백 1채널. 정확한 크기와 3채널 여부 미결 (`0003`) |
| 출력 캔버스 크기 | `tps_flow(shape=(h,w))` — 크롭과 같은 크기. 확대 검토했으나 확대 없이 0.8px 까지 복원되므로 우선순위 낮음 |
| 재시도 파라미터 순서 | 보간법 3종이 초안. 제어점 변위 스케일 조정도 후보 (`0006`) |
| 송장에 바코드가 여러 개일 때 | `PipelineResult.detected` 는 단수인데 `DecodeResult.candidate_count` 는 복수 전제. AI·SW 공통 미결 (`0001`) |
| 심볼로지 | Code128 가정. QR 이 들어오면 반사 대응(설계 §7)이 전부 다시 설계 (`0001`) |
| 디코더 | zxing-cpp 하나로만 측정. 다른 걸 고르면 위의 모든 구간 경계가 움직임 (`0006`) |
