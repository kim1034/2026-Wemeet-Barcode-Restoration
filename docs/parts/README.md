## 서로 막는 관계 — 이것만 알면 순서가 보입니다

```
[결정 0001] 바코드 종류 확정  ── 막는다 ──▶  데이터 수집·라벨링·합성 전부
    팀장 · 9월 1주차 · 최우선

[결정 0006] 디코더 선정      ── 막는다 ──▶  평가 기준, 재시도 순서
    SW · 9월 1주차

합성 데이터 v1              ── 막는다 ──▶  기하 추정 학습
    데이터 · 9월 3주차

[결정 0002] 검출 모델 확정   ── 막지 않는다 ──▶  기하 추정 학습
    AI · 9월 4주차              (최종 학습·평가 전에만 필요하다)
```

**심볼로지(0001)가 가장 급합니다.** 이게 틀리면 모아둔 데이터가 전부 무효가 됩니다. 현장 확인이 필요해서 코드로 해결할 수 없습니다.

### 촬영 해상도(0004)도 같이 급해졌습니다 — 2026-08-28

[합성 스파이크](../experiments/2026-08-28-synthesis-spike/README.md)에서 나온 것입니다.

```
[결정 0004] 촬영 해상도  ── 정한다 ──▶  Stage 2 가 필요한 비율 자체
    데이터파트 · 0001 과 같은 방문에서 확인
```

바코드가 사진에서 **가로 몇 px 을 차지하는지**가 지배 변수입니다.
가장 얇은 막대가 5px 이면 어지간히 휘어도 디코더가 그냥 읽고(보정 없이 원통 70°까지),
2px 근처면 같은 왜곡에 깨집니다. **현장이 5px 을 준다면 Stage 2 가 할 일이 거의 없습니다.**

`0001` 을 물어보러 갈 때 **실패한 사진 10~20장을 같이 받아 오면** 이 값이 바로 나옵니다.

### 검출 확정을 기다리지 마세요

기하 추정은 **합성 크롭으로 학습**하므로 검출 모델이 없어도 시작할 수 있습니다. 합성 데이터가 나오는 9월 3주차부터 바로 붙으면 됩니다.

다만 **최종 학습·평가는 실제 검출기가 만든 크롭으로** 해야 합니다. 크롭 여백이나 회전 보정 정도가 합성과 다르면 분포가 어긋나서 실촬영 성능이 떨어집니다. 순서는 이렇게 됩니다.

```
합성 크롭으로 먼저 학습  →  검출 확정 후 그 크롭으로 미세조정·재평가
```

"검출이 끝나야 기하를 시작한다"고 읽으면 AI파트가 9월 4주차까지 손을 놓고 기다리게 됩니다. 그러면 10월이 무너집니다.

대신 두 가지를 조심하세요.

1. **방향** — `src`/`dst`를 뒤집으면 왜곡이 두 번 적용됩니다. 약한 왜곡에서는 우연히 맞아 보여서 놓치기 쉽습니다. **만든 데이터를 정답 제어점으로 직접 펴서 디코더에 넣어보는 것**이 가장 싼 검증입니다
2. **왜곡 상한** — 가장자리 모듈이 1px 이하로 압축되는 왜곡은 학습에 넣어도 배울 수 없습니다. 정보가 없는 것을 맞추라고 하는 셈입니다
