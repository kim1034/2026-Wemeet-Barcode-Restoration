# 구겨진 바코드를 코드로 만드는 법

**누가 읽나**: 팀원 전체. 미리 알아야 하는 것 없습니다.
**왜 읽나**: 2단계(기하 추정) 모델을 학습시킬 데이터를 우리가 직접 만들어야 하고,
그걸 어떻게 만드는지 다 같이 알고 있어야 합니다.

---

## 1. 왜 데이터를 직접 만드나

사진을 모아서 쓰면 안 되냐고 물으면, **안 됩니다.** 이유가 하나뿐인데 결정적입니다.

우리가 2단계 모델에게 가르치려는 건 이겁니다.

> "이 구겨진 사진에서, **원래 여기 있던 막대가 지금 어디로 밀려났는지**"

그런데 구겨진 송장 사진을 눈으로 보고 **"이 막대가 펴졌을 때 왼쪽에서 137번째 픽셀이었다"**
를 적어낼 방법이 없습니다. 사람이 볼 수 없습니다.

1단계(검출)는 다릅니다. "바코드가 사진 어디 있냐"는 눈에 보이니까 사람이 네모를 그려주면 됩니다.

| | 정답을 사람이 적을 수 있나 |
|---|---|
| 1단계 — 바코드가 어디 있나 | **예** (네모 그리기) |
| 2단계 — 얼마나 휘었나 | **아니오** |

그래서 **정답을 아는 유일한 방법은 우리가 직접 구기는 것**입니다.
얼마나 구겼는지 우리가 넣었으니까 정확히 압니다.

---

## 2. 만드는 순서 — 여섯 걸음

```
① 깨끗한 바코드를 그린다
② 종이가 어떻게 휘었는지 정한다
③ 그 모양대로 그림을 찌그러뜨린다
④ 정답을 뽑는다          ← 이게 우리가 원하는 것
⑤ 빛과 반사를 얹는다
⑥ 사진처럼 흐리게 만든다
```

### ① 깨끗한 바코드를 그린다

`python-barcode` 라이브러리에 번호를 넣으면 막대 그림이 나옵니다.
번호를 우리가 정했으니 **정답 번호를 이미 알고 있습니다.**

### ② 종이가 어떻게 휘었는지 정한다

여기가 이 문서의 핵심입니다. 종이 모양을 **높이 지도**로 정합니다 —
"이 자리에서 종이가 얼마나 기울어져 있나"를 숫자로 적어둔 표입니다.

휘는 방식은 세 가지뿐입니다.

| 이름 | 어떻게 생겼나 | 현장에서 |
|---|---|---|
| **원통** | 전체가 둥글게 감김 | 화물이 둥글어서 라벨이 감긴 것 |
| **물결** | 넓었다 좁았다 반복 | 비닐 리플, 완만한 주름 |
| **접힘** | 한 선을 기점으로 꺾임 | 송장이 한 번 접힌 자국 |

**구깃구깃한 것은 네 번째 방식이 아니라, 물결을 크기별로 여러 개 겹친 것**입니다.
큰 물결 하나에 작은 물결 여러 개를 얹으면 구김처럼 보입니다.

### ③ 그 모양대로 그림을 찌그러뜨린다

**가로로만 찌그러뜨립니다.** 위아래로는 아무것도 안 합니다.

이게 이상하게 들리는데, 실험으로 확인한 사실입니다.

> 막대를 위아래로 32픽셀까지 물결치게 만들어도 **바코드는 그대로 다 읽힙니다.**
> 막대가 세로로 길기 때문에, 위아래로 밀려도 **막대의 굵기와 간격이 안 변하니까요.**
> 디코더는 굵기와 간격만 봅니다.

그래서 정보를 망가뜨리는 건 **가로 방향으로 눌리는 것**뿐입니다.
우리는 그것만 만듭니다. 할 일이 반으로 줄어듭니다.

### ④ 정답을 뽑는다

펴진 상태에 격자점을 규칙적으로 찍어둡니다. 가로 6개 × 세로 3개 = **18개**.

```
펴진 상태 (우리가 정한 격자)        찌그러진 뒤 (그 점들이 밀려간 위치)
 ●  ●  ●  ●  ●  ●                  ●  ● ●    ●   ●  ●
 ●  ●  ●  ●  ●  ●        ───▶      ●  ● ●    ●   ●  ●
 ●  ●  ●  ●  ●  ●                  ●  ● ●    ●   ●  ●
       ↑                                   ↑
   항상 똑같다                    이게 정답. 모델이 맞혀야 하는 것
```

모눈종이를 구겨놓고 "교차점이 어디로 갔는지 짚어라"와 같습니다.
다만 바코드에는 모눈이 안 그려져 있으니, 모델은 **막대 간격이 변한 걸 보고 역산**해야 합니다.

### ⑤ 빛과 반사를 얹는다

②에서 만든 높이 지도가 여기서 한 번 더 쓰입니다.
종이가 기울어진 방향을 알면 **빛이 어디서 반사되는지 계산할 수 있습니다.**

이게 왜 중요하냐면 — 반사를 그냥 흰 타원으로 아무 데나 얹으면
**"번쩍이는 자리"와 "휘어진 자리"가 아무 상관이 없어집니다.**
실제 현장에서는 휘어진 곳에서 번쩍이고, 그게 모델에게 강한 단서입니다.
같은 높이 지도를 쓰면 그 관계가 공짜로 맞습니다.

실제로 재봤습니다. **반사가 접힌 자리에서 평균 0.7픽셀 안에 생깁니다.**
아무렇게나 얹으면 86.8픽셀 떨어집니다.

그리고 **반사는 곱하지 않고 더합니다.** 곱하면 검은 막대가 계속 검게 남습니다
(0 × 무엇 = 0). 실제 비닐 반사는 검은 막대까지 하얗게 덮어버립니다.
그게 바코드를 못 읽게 만드는 진짜 원인이라, 더해야 맞습니다.

### ⑥ 사진처럼 흐리게 만든다

초점 흐림, 카메라 노이즈, JPEG 압축을 약하게 넣습니다.
그리고 **검출기가 자른 것처럼** 크롭 여백을 조금 흔들고 몇 도 돌립니다.

## 3. 조심할 것 딱 세 개

팀원이 이 코드를 만지게 되면 여기서 틀릴 수 있습니다.

### 조심 1 — 방향을 거꾸로 하면 티가 안 납니다

"펴진 것 → 휜 것" 방향과 "휜 것 → 펴진 것" 방향을 **거꾸로 쓰기 쉽습니다.**
그리고 무서운 건, **약하게 휜 데이터에서는 거꾸로 해도 잘 읽힙니다.**

실제로 사전 실험에서 이 실수를 했고, 35도에서 100% 읽혀서 정상으로 보였습니다.
50도에서 갑자기 0%가 나와서 발견했습니다.

**디코딩이 성공하는지로는 이 오류를 절대 못 잡습니다.**
그래서 수학 공식과 직접 비교하는 검사를 넣어뒀습니다.

### 조심 2 — 바코드를 잘라먹으면 끝입니다

바코드에는 "여기서 시작·여기서 끝" 표시가 양 끝에 있습니다.
그게 잘리면 **어떤 방법으로도 못 읽습니다.**

| 자른 정도 | 되펴서 읽기 |
|---|---|
| 여유 있게 크게 | 성공 |
| 딱 맞게 | 성공 (아슬아슬) |
| 조금 잘라먹음 | **실패** |

1단계에 부탁할 것: **여유를 두고 크게 잘라주세요.** 주변 글자가 들어와도 괜찮습니다.

### 조심 3 — 이미지를 저장하지 않습니다

수만 장을 파일로 만들면 수십 기가라 8명이 각자 받아야 합니다.
대신 **"어떻게 구겼는지 적은 쪽지"만 저장**하고, 필요할 때 그 쪽지로 다시 만듭니다.

쪽지 수만 장이 몇 메가라 깃허브에 들어갑니다. 같은 쪽지는 **항상 똑같은 그림**을 만듭니다.

덕분에 좋은 게 하나 더 있습니다. 바코드 종류가 다른 것으로 밝혀지거나
디코더를 바꾸게 되면, **쪽지를 다시 돌리면 끝**입니다.

## 4. 한 장에 무엇이 들어가나 — 다 섞지 않습니다

여기가 오해하기 쉬운 곳입니다.

**여섯 걸음은 모든 장이 다 거칩니다.** 공장 라인처럼요. 그런데 **휘는 방식은 골라 씁니다.**

| | 한 장에 들어가나 |
|---|---|
| **감김** (둥근 화물) | 거의 항상. 다만 조연으로 약하게 |
| **접힘** (한 번 접힌 자국) | 30%의 장에 |
| **물결** (비닐 리플) | 30%의 장에 |
| **구김** (물결 세 개 겹침) | 30%의 장에 |
| 감김만 | 10%의 장에 |

세 가지를 똑같이 나눈 이유는 **어느 것을 더 넣어야 하는지 아무도 모르기 때문**입니다.
현장 사진이 없어서 근거를 못 만듭니다. 그래서 균등하게 넣고, 결과를 **휘는 방식별로 따로
보고**합니다. 나중에 현장 주름이 어떤지 알게 되면 그 칸을 보면 됩니다.

접힘과 물결이 같은 장에 들어가는 일은 드뭅니다.

### 왜 다 섞으면 안 되나

휘는 세기에 **예산**이 있습니다. 너무 세게 휘면 정보가 죽어서 아무도 못 읽으니까요.

성분을 여러 개 넣으면 그 예산을 **나눠 씁니다.** 넷을 넣으면 각각이 4분의 1 세기가 되고,
결과는 "살짝 휜 것"입니다. 그러면 **1단계에서 그냥 읽혀서 2단계가 할 일이 없습니다.**

재봤습니다.

| | 2단계가 값을 하는 비율 |
|---|---|
| 성분을 골고루 섞음 | **2%** |
| 한두 개에 몰아줌 | **12~18%** |

**세기를 한두 곳에 몰아줘야 쓸 만한 데이터가 됩니다.**

### 한 장의 실제 모습

```
1) 접힌 송장 (30%)
   감김 30% + 접힘 70% (폭 4px, 22° 비스듬히)
   번쩍임 있음, 살짝 흐림

2) 감기기만 한 것 (10%)
   감김 100%
   번쩍임 없음, 거의 안 흐림

3) 구겨진 것 (30%)
   감김 20% + 물결 세 개 겹침 (큰 것·중간·작은 것)
   번쩍임 강함
```

**번쩍임과 흐림은 0일 수도 있습니다.** 세기를 0부터 뽑기 때문에 어떤 장은 반사가 아예 없고
어떤 장은 안 흐립니다. 현장 사진도 다 번쩍이는 게 아니니까요.

## 5. 실제로 만드는 순서

```
① 쪽지 뽑기      27만 장분. 파라미터만 뽑으니 즉시 끝난다
② 라벨 붙이기    실제로 그려서 읽어보고 "2단계가 필요한 장인가" 판정
                 쓸 장 3만 개를 채우면 멈춘다. 나머지는 버린다
③ 평가용 골라내기  "2단계가 필요한 장"만 모아 그림으로 저장
④ 학습          쪽지를 읽어 그 자리에서 그림을 만들어 먹인다
```

| 단계 | 시간 |
|---|---|
| ① 쪽지 27만 장 | 즉시 |
| ② 라벨 붙이기 (학습 3만 장) | 8코어로 **약 3시간** |
| ③ 평가 세트 1500장 | 8코어로 약 4분 |
| ④ 학습 중 생성 | 초당 500장 이상 |

②가 오래 걸리는 이유는 **한 장마다 실제로 그리고 두 번 읽어보기** 때문입니다 —
구기기 전에 한 번, 되편 다음에 한 번. 그래야 "2단계가 필요한 장인가"를 알 수 있습니다.

그리고 **쓸 만한 장이 드뭅니다.** 아홉 장을 그려야 쓸 장 하나가 나옵니다. 바코드가 크게
찍힌 장일수록 더 드물어서, 27만 장을 그려 3만 장만 씁니다. 그림을 저장하지 않으니
버리는 비용은 CPU 시간뿐입니다.

### 어떤 장을 쓰고 어떤 장을 버리나

읽어본 결과로 네 무더기가 나옵니다.

| 무더기 | 뜻 | 학습에 |
|---|---|---|
| **2단계가 필요한 장** | 그냥은 못 읽는데 되펴면 읽힌다 | **50%** |
| **되펴도 못 읽지만 주름은 보이는 장** | 막대가 너무 얇아 못 읽을 뿐, 어떻게 휘었는지는 보인다 | **35%** — 어려운 문제집 |
| **그냥 읽히는 장** | 2단계를 부르지도 않는다 | **15%** — 쉬운 문제 몇 개만 |
| **번쩍임에 먹힌 장** | 하얗게 타서 주름 자체가 안 보인다 | **0%** — 버린다 |

마지막 무더기를 버리는 이유는 **답이 없는 문제를 풀라고 시키는 셈**이기 때문입니다.
모델이 "안 보여도 대충 찍는" 버릇을 배웁니다.

"그냥 읽히는 장"을 15%로 줄인 이유는 반대입니다. **쉬운 문제만 잔뜩 풀면 답을 작게 쓰는
버릇**이 듭니다. 그러면 정작 많이 휜 장에서 덜 펴게 됩니다.

### 평가용은 세 벌로 나눕니다

바코드가 사진에서 몇 픽셀인지에 따라 결과가 크게 달라져서, **해상도별로 세 벌** 만듭니다.

| 세트 | 가장 얇은 막대 | 장수 |
|---|---|---|
| 저해상도 | 약 2 px | 500 |
| 중간 | 약 3 px | 500 |
| 고해상도 | 약 5 px | 500 |

그러면 모델 비교 결과가 **"저해상도에서는 A가 낫고 고해상도에서는 B가 낫다"** 로 나옵니다.
나중에 현장 카메라가 어떤지 알게 되면 **그 칸을 보면 됩니다.**

## 6. 지금 가장 급한 것 — 카메라 숫자 두 개

실험하다가 예상 밖의 사실을 알게 됐습니다.

> **바코드가 사진에서 몇 픽셀을 차지하는지가, 휜 정도보다 더 중요합니다.**

바코드는 **막대 굵기의 비율**로 읽습니다. 가장 얇은 막대가 5픽셀이면
꽤 휘어도 비율이 안 깨져서 **그냥 읽힙니다.** 2픽셀이면 같은 정도로 휘어도 깨집니다.

그래서 2단계가 실제로 필요한 경우가 얼마나 되는지가 여기서 갈립니다.

| 가장 얇은 막대 | 2단계가 값을 하는 비율 |
|---|---|
| 약 2픽셀 | **12~18%** |
| 약 3~4픽셀 | 7% |

**현장 카메라가 5픽셀을 준다면 2단계가 할 일이 거의 없습니다.**
2픽셀 근처라면 핵심이 됩니다.

**실패한 사진은 받을 수 없게 됐습니다.** 대신 **숫자 두 개**만 받으면 계산됩니다.

1. 카메라 **가로 해상도** (1920px? 4K?)
2. 카메라가 **보는 가로 범위** (컨베이어 폭 60cm? 30cm?)

```
가장 얇은 막대(px) = (가로 해상도 ÷ 보는 범위 mm) × 0.33mm
```

0.33mm 는 송장 바코드의 표준 막대 굵기입니다.

| 해상도 | 보는 범위 | 가장 얇은 막대 |
|---|---|---|
| 1920px | 60cm | **1.1 px** |
| 1920px | 30cm | 2.1 px |
| 4K | 60cm | 2.1 px |
| 4K | 30cm | 4.2 px |

**컨베이어 전체를 한 대로 찍으면 1~2px 이 나옵니다.** 기획서나 장비 명세에 이미 있을 수 있습니다.

이것도 못 받으면 §5의 세 벌 평가 세트가 대비입니다 — 어느 쪽이든 답이 준비됩니다.
