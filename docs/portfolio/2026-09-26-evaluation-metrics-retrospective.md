# 모델을 개선하기 전에 평가 지표부터 고정한 이유

- **작성일:** 2026-09-26
- **프로젝트:** WE-Meet 난인식 바코드 판독 파이프라인
- **범위:** Stage 2 기하 추정 모델의 평가 설계와 실험 정리
- **작성 시점 상태:** 평가 프로토콜 v1 초안을 [PR #15](https://github.com/kim1034/2026-Wemeet-Barcode-Restoration/pull/15)에 제출했다. 팀 검토·평가 코드 반영·재측정은 남아 있다.

> 같은 “좌표 오차”라는 이름을 썼다고 같은 성능을 측정한 것은 아니었다.
> ResNet 성능을 높일 방법을 찾는 과정에서, 무엇을 개선했다고 말할 수 있는지부터
> 정해야 한다는 점을 확인했다.

## 배경 — ResNet을 기준으로 1차 통합을 준비하던 시점

우리 파트는 Stage 2를 담당한다. 잘라낸 바코드 이미지에서 16×3 제어점의
좌표를 예측하면, Stage 3가 그 좌표로 이미지를 펴고 Stage 4가 번호를 읽는다.
Stage 2의 출력은 48개 점의 x/y 좌표이며, 판독 성공은 뒤 단계와 연결해야 확인된다.

Stage 2에서는 ResNet18-C3와 MobileNetV3-Small을 각각 실험했다.
이후 ResNet을 기준선으로 확정하고 강민이 1차 구현을 진행하는 동안,
MobileNet 실험 담당자는 ResNet 성능 개선 방향을 준비하기로 했다.

학습률·loss·데이터 보강을 검토하려면 먼저 “기존보다 좋아졌다”는 판단이
가능해야 했다. 그래서 모델 구조를 추가로 바꾸기에 앞서, 기존 결과와
평가 코드를 대조했다.

## 발견 1 — 숫자의 단위가 같아도 계산 방식은 달랐다

기존 ResNet 보고서에는 평균 좌표 오차가 **1.3723px**, MobileNet spatial
보고서에는 **1.833px**로 기록되어 있었다. 두 값을 나란히 놓으면 ResNet이
더 정확해 보이지만, 그대로 비교할 수 없었다.

| 확인 항목 | ResNet 기존 결과 | MobileNet 제공 보고서 |
|---|---|---|
| 평가 집합 | validation 2,976장 | 난인식 target eval 1,500장 |
| 좌표 오차 | x/y 축별 절대오차를 펼쳐 집계 | 점별 2차원 거리로 기술 |
| 전체 집계 | 배치마다 계산한 통계를 평균 | 원본 코드·원시 기록 확인 필요 |
| 판독 평가 | 보고서 시점 미측정 | GT 캔버스·전체 TPS 경로의 결과 존재 |

ResNet의 [평가 코드](https://github.com/kim1034/2026-Wemeet-Barcode-Restoration/blob/9dfb47918b40dafc20dbc5a282381bd90f12cdfd/scripts/train_geometry.py)를
확인한 것이 결정적이었다. x/y 오차를 한 배열로 펼친 뒤 평균과 P95를
계산하고, 마지막에는 배치별 통계를 평균하고 있었다.

예를 들어 x 오차가 3px, y 오차가 4px인 한 점에서 축별 절대오차 평균은
3.5px지만, 정답 점과 예측 점 사이의 거리는 5px다.
또 배치별 P95의 평균은 전체 데이터의 P95가 아니다.

기존 숫자가 쓸모없어진 것은 아니다. **무엇을 계산했는지 이름과 조건을
명시해야 한다**는 뜻이다. 우리는 이전 값을 보존하고, 새 비교에서는 원본 crop
기준의 2D EPE를 전체 제어점에 대해 계산하도록 정리했다.
과거의 요약값만으로 새 EPE를 환산하지 않고 재추론·재집계를 하기로 했다.

## 발견 2 — 바코드가 “읽혔다”와 “맞게 읽혔다”는 달랐다

바코드 판독의 최종 목적은 올바른 번호를 반환하는 것이다.
디코더가 문자열을 반환하거나 체크섬을 통과했다는 이유만으로 성공을 세면
틀린 번호까지 성능에 포함될 수 있다.

공유된 MobileNet spatial 실험 보고서에는 1,500장 중 정답 1,158장,
오독 9장, 무응답 333장으로 기록되어 있다. 정답률은 77.20%지만,
값이 나왔다는 이유만으로 세면 오독 9장도 성공에 들어간다.
이 수치는 이번 회고에서 재실행한 결과가 아니며,
[실험 이력 정리](https://github.com/kim1034/2026-Wemeet-Barcode-Restoration/blob/d05485223f91551773467caea39f8d78dc4b5659/docs/experiments/README.md)에
원자료 확인이 필요한 보고값으로 남겼다.

여기서 평가 결과를 **정답·오독·무응답**으로 분리했다.
오독을 무응답과 함께 실패로만 묶으면, 같은 실패율 안에서 잘못된 번호가
더 많이 출력되는 변화를 놓칠 수 있기 때문이다.

난인식의 분모에도 같은 문제가 있었다.
평가자는 정답을 알기 때문에 1차 디코더의 오독도 실패로 분류할 수 있다.
하지만 실제 파이프라인은 그 문자열이 오독인지 모른 채 조기 종료할 수 있다.

그래서 **정답 판정상 1차 실패 집합의 구제율(RR_H)**과
**실제 1차 무응답 집합의 구제율(RR_U)**을 구분했다.
평가 때 정답을 보고 오독만 다시 모델에 보내는 경로를 현장 성능으로 발표하지
않도록 하기 위한 결정이다.

## 발견 3 — 좋은 실험 조건이 실제 운영에서도 주어지지는 않았다

MobileNet 보고서의 판독 결과는 합성 정답의 펼친 크기
`h_flat, w_flat`를 사용하고, TPS를 전체 격자에서 계산한 조건이었다.
이 조건은 모델의 기하 예측을 분석하는 데 도움이 되지만,
실제 사진에는 펼친 정답 크기가 주어지지 않는다.

따라서 77.20%를 그대로 통합 파이프라인의 성적으로 부를 수 없다.
같은 모델이라도 출력 크기, TPS 축소, 디코더, 재시도 정책에 따라 판독 결과가
달라질 수 있으므로 이 조건까지 함께 고정해야 한다.

우리는 평가를 **좌표 단독, oracle 진단, 실전 crop 경로, 전체 E2E**로 구분했다.
정답 정보를 이용한 진단 실험은 그 사실을 표 제목에 밝히고, 실제 입력과
예측만 사용하는 경로에서 통합 성능을 별도로 확인하기로 했다.

## 결정 — 논문의 평가 관점을 우리 목적에 맞게 적용했다

관련 논문에서 완성된 지표 묶음을 그대로 가져오기보다는,
각 논문의 어떤 평가 관점이 우리 문제에 필요한지 확인했다.

- **Muallim 등의 바코드 복원 연구(CMES 2025)**는 실제 decodability를 핵심 지표로
  둔다. 우리도 보정 뒤 번호를 정확히 읽었는지를 주지표로 삼는 근거로 사용했다.
  [논문 §3.3.1](https://www.techscience.com/CMES/v143n3/62816/html)
- **DewarpNet(ICCV 2019)**은 기하 보정 뒤 OCR 성능을 CER/ED로 평가한다.
  보정의 가치를 최종 인식 작업으로 확인하는 관점을 참고했다. 우리에게는
  번호 전체가 맞아야 하므로 문자 일부가 맞은 것을 성공으로 세지 않는다.
  [논문 §5.1·§5.4](https://www3.cs.stonybrook.edu/~cvl/projects/dewarpnet/storage/paper.pdf)
- **Baker 등의 optical flow 평가 연구(IJCV 2011)**에서는 endpoint error와
  백분위수 통계를 참고했다. 이를 원본 crop의 48개 제어점에 적용했다.
  [논문 §4.1·§4.2](https://link.springer.com/content/pdf/10.1007/s11263-010-0390-2.pdf)

그 결과 정리한 지표의 역할은 다음과 같다.

| 답하려는 질문 | 지표 |
|---|---|
| 원래 정답을 못 읽던 바코드를 얼마나 살렸나? | 난인식 정답 구제율 |
| 틀린 번호를 내보내지는 않았나? | 오독률과 정답·오독·무응답 건수 |
| 기하 좌표를 어느 방향에서 얼마나 틀렸나? | EPE mean/P95, x/y MAE |
| 실제 사용 흐름에서 처리할 수 있나? | Stage 2 및 E2E p50/p95 지연 |

SSIM/PSNR은 정렬된 합성 이미지의 보조 분석에는 사용할 수 있다.
다만 이미지가 비슷해졌다는 것만으로 번호를 정확히 읽었다고 결론낼 수 없고,
Stage 2의 직접 출력도 좌표이므로 필수 모델 선택 기준에서는 제외했다.

구제율의 분모, 오독 집계, oracle/실전 경로 분리 등은 **프로젝트에 맞게
추가한 규칙**이다. 이 규칙 전체를 특정 논문이 정한 표준이라고 표현하지 않았다.
상세 계산법은 [평가 프로토콜 v1 초안](https://github.com/kim1034/2026-Wemeet-Barcode-Restoration/blob/d05485223f91551773467caea39f8d78dc4b5659/docs/decisions/0005-평가-지표-체계.md)에 있다.

## 배운 점 — 평가도 구현과 같은 수준으로 관리해야 한다

**첫째, 지표는 이름만으로 정의되지 않는다.**
계산식, 좌표계, 분모, 집계 방법, 실패 처리까지 같아야 모델을 비교할 수 있다.
EPE와 P95의 간단한 계산 예제를 문서에 넣은 것도 구현자가 같은 뜻으로
계산하는지 확인하기 위해서다.

**둘째, 모델 개선과 전체 시스템 개선을 구분해야 한다.**
좌표 오차가 줄어든 것, 바코드 구제율이 오른 것, E2E가 빨라진 것은 각각
확인해야 할 결과다. 한 단계의 지표로 다른 단계의 성과까지 주장하지 않기로 했다.

**셋째, 평가셋이라는 이름만으로 최종 검증이 되는 것은 아니다.**
기존 1,500장은 이미 모델 결과를 확인하고 캔버스·재시도 설정을 검토하는 데
사용됐다. 앞으로 이 집합을 보고 개선안을 고르면 개발 벤치마크로 기록하고,
최종 결론은 새 holdout 또는 설정을 잠근 실촬영 eval에서 확인해야 한다.

**넷째, 오독 0건도 표본 수와 함께 해석해야 한다.**
유한한 평가에서 오독을 관측하지 못했다고 실제 발생 가능성이 0이 되는 것은 아니다.
정답률·오독률에 분자/분모와 신뢰구간을 함께 적고, 학습 seed에 따른 변동도
별도로 보고하도록 했다. 신뢰구간은 [NIST Wilson 지침](https://itl.nist.gov/div898/handbook/prc/section2/prc241.htm)을
참고했다.

## 이번에 완료한 것과 아직 남은 것

완료한 일은 **평가의 기준을 문서로 구체화한 것**이다.
논문 근거를 연결하고, 계산 방식의 차이를 확인하고, 이전 실험 수치의 조건을
정리했으며, 후속 ResNet 개선 실험을 같은 기준에서 진행할 순서를 마련했다.
평가 문서와 실험 목록은 PR #15에 올렸고 저장소 자동 검사를 통과했다.

아직 평가 코드가 v1 규칙으로 바뀐 것은 아니다.
기존 모델을 새 기준으로 재측정하지 않았으며, 이 문서화로 모델 성능이
높아졌다고 주장할 수는 없다. PR의 팀 검토와 기획서 KPI 변경 승인도 별도다.

다음 단계는 강민의 1차 구현에 평가 규칙을 연결해 **ResNet 기준선 성적표**를
채우는 것이다. 이후 학습률, loss, 데이터 보강을 한 번에 하나씩 바꾸면서
구제율과 오독률이 어떻게 변하는지 확인한다.
이번에 정한 기록 방식은 그 개선이 실제 효과인지, 측정 조건이 바뀐 결과인지
설명할 수 있게 하기 위한 준비다.
