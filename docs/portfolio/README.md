# 개발 포트폴리오 — 결정과 배움의 기록

이 폴더는 WE-Meet 바코드 판독 프로젝트에서 **어떤 문제를 발견했고, 무엇을
근거로 결정했으며, 개발하면서 무엇을 배웠는지** 기록하는 공간입니다.
결과보고서·발표·개인 포트폴리오를 준비할 때 판단 과정과 근거를 다시 찾을 수
있도록 실제 작업과 연결해 남깁니다.

## 무엇을 남기나요?

- **결정:** 모델·데이터·평가 방식·인터페이스를 선택한 이유와 검토한 대안.
- **발견:** 예상과 실제 결과가 달랐던 지점, 코드나 실험에서 찾은 문제.
- **해결 과정:** 원인을 어떻게 확인했고, 어떤 변경을 했으며, 무엇으로 검증했는지.
- **배운 점:** 다른 실험이나 다음 프로젝트에도 적용할 원칙.
- **남은 질문:** 아직 검증하지 못한 가정, 후속 실험과 그 판단 기준.

작업이 진행되어 의미 있는 결정이나 배움이 생기면 한 주제씩 기록합니다.
실험값이 없는 설계 회고도 남길 수 있지만, 설계·구현·검증의 완료 상태를 구분합니다.

## 작성 방식

파일 이름은 `YYYY-MM-DD-topic.md`를 사용합니다. 글을 추가하면 위 목록에도
링크를 넣습니다. 한 글은 다음 흐름으로 작성합니다.

1. **배경과 역할:** 어떤 단계에서 어떤 문제를 해결하려 했는가.
2. **발견한 문제:** 당시 판단을 어렵게 만든 조건과 확인한 증거.
3. **결정과 이유:** 선택한 방법, 대안, 포기한 이점이나 남은 비용.
4. **실제 결과:** 완료한 변경·측정·검증과 아직 하지 않은 일.
5. **배운 점과 다음 행동:** 재사용할 원칙, 후속 작업의 확인 기준.

수치를 쓸 때는 데이터·분모·측정 경로·출처를 함께 적습니다.
관측한 사실, 그 사실에 대한 해석, 앞으로 할 계획을 구분하고,
아직 측정하지 않은 개선을 성과로 표현하지 않습니다.
팀 작업과 개인 기여도는 확인할 수 있는 범위에서 기록합니다.

결정이 바뀌면 날짜와 바뀐 이유를 추가합니다. 과거 판단을 지워서 처음부터
정답을 알고 있었던 것처럼 만들지 않습니다.
