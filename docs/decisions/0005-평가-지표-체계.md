# 0005. 평가 지표 체계 — Stage 2 평가 프로토콜 v1

- **문서 버전**: `stage2-eval-v1` · 2026-09-26
- **상태**: 실험용 지표·집계 규칙 고정안. 이 PR로 팀 검토하며 평가 코드 반영·재측정은 후속 작업
- **기준 모델**: ResNet18-C3. MobileNet 결과는 기존 비교 실험으로 보존
- **범위**: Stage 2 개선 실험, Stage 2→3→4 평가, 1차 통합 및 결과보고서·발표
- **기획서 KPI**: 멘토·지도교수 확인 전. 본 문서가 사업단 목표 수치나 배포 승인을 대신하지 않는다
- **실험 목록·기존 수치·후속 순서**: [실험 기록](../experiments/README.md)

> **발표의 중심은 “얼마나 많은 바코드를 정확히 읽게 했는가”다.**
> 필수 지표는 **난인식 정답 구제율 + 오독률 + 제어점 EPE + 지연시간**이다.
> 지표 정의와 목표 수치는 구분한다. 근거 없이 구제율 90%나 EPE 2px를 합격선으로 정하지 않는다.
> 아래 v1이 이 문서 말미의 이전 제안보다 우선한다. 기존 수치는 계산법을 확인하기 전까지 v1 결과로 바꾸어 부르지 않는다.

## 1. 논문에서 차용한 것과 프로젝트에서 정한 것

| 근거 | 논문에서 확인한 평가 | 우리 프로젝트에 적용 | 그대로 가져오지 않는 것 |
|---|---|---|---|
| **Muallim et al., CMES 2025 [R1], §3.2·§3.3.1** | 바코드 복원 후 decodability를 핵심 지표로 사용하며 추론 시간·모델 크기도 보고 | 복원 이후 실제 판독 결과와 계산 비용을 함께 평가 | 생성형 복원 구조, 논문의 데이터셋 점수·목표치 |
| **Das et al., DewarpNet, ICCV 2019 [R2], §5.1·§5.4** | 기하 보정 결과를 이미지 유사도와 보정 후 OCR의 CER/ED로 평가 | 보정의 가치를 최종 인식 작업으로 검증 | 바코드 번호의 부분 일치를 성공으로 취급하는 CER/ED |
| **Baker et al., IJCV 2011 [R3], §4.1 식 (23)·§4.2** | 좌표 차이의 2차원 endpoint error 및 평균·백분위수 보고 | 원본 crop 좌표계에서 48점의 EPE mean/P95 계산 | 광학 흐름의 모든 픽셀을 평가한 결과와 48점 평가의 직접 비교 |
| **NIST 통계 지침 [R4]** | 비율의 Wilson 신뢰구간 | 정답률·오독률에 표본 수와 95% 구간 병기 | 작은 표본의 관측 0%를 실제 발생확률 0으로 해석 |

**우리의 추가 규칙**은 정답 문자열 완전 일치, 오독/무응답 구분, 난인식 분모,
oracle/실전 경로 분리, p95 지연, 실험 고정 조건이다. 이 전체 규칙이 어느 한
논문의 표준이라고 주장하지 않는다. 논문 간 데이터·손상·디코더가 다르므로 논문
점수와 우리 점수를 같은 순위표에 넣지 않는다.

SSIM/PSNR은 정렬된 합성 이미지가 있을 때 보조 분석에 쓸 수 있지만 **Stage 2의
필수 지표나 모델 선택 기준은 아니다**. 실촬영에서는 별도로 펴서 찍은 이미지가
픽셀 정렬 GT가 된다고 가정하지 않는다.

## 2. 평가 단위와 정답 판정

평가 단위는 **이미지 한 장, 정답 바코드 하나**다. 동일 송장·동일 원본으로 만든
여러 변형은 같은 `group_id`를 가지며 학습/검증/최종평가 사이에 나누지 않는다.
이미 발행된 데이터는 그룹 분리 여부를 감사하고 확인 전에는 독립성을 보장했다고 쓰지 않는다.

`D0`는 보정 전 고정 디코더의 반환값, `DM`은 평가 경로가 최종 반환한 값,
`GT`는 정답 문자열이다. 심볼로지는 Code128으로 고정한다.

- **C (correct)**: 심볼로지와 payload가 정답과 완전히 같다.
- **W (wrong)**: 값을 반환했지만 정답과 다르다. 체크섬 통과만으로 C가 되지 않는다.
- **U (unreturned)**: 미검출·미판독·신뢰도 거절·처리 실패 등으로 값을 반환하지 못했다.
- `C + W + U = N`. U의 원인은 별도 기록한다. 실패한 샘플도 분모에서 빼지 않는다.
- 선행 0, 대소문자, 공백을 임의로 제거하지 않는다. 디코더별 payload 변환이
  필요하면 정답을 보지 않는 공통 규칙을 실행 설정에 명시한다.
- 여러 후보·재시도 중 **GT와 맞는 결과를 골라 주지 않는다**. 고정된 운영 정책이
  선택한 한 결과를 채점한다. 처음 반환한 오독 때문에 조기 종료되면 최종 결과도 W다.
- GT는 채점과 사전 데이터 분류에만 사용한다. 추론·재시도·조기 종료·후보 선택에 넘기지 않는다.
- 필수 데이터 누락·중복 ID·GT 손상이 있으면 실행을 무효로 표시하고 수정 후 전수 재평가한다.
  처리되지 않은 샘플을 몰래 제거한 부분 실행은 정식 성적이 아니다.

## 3. 주지표: 판독 성능과 오독

모든 비율은 아래 식에 100을 곱한 %로 보고한다. `N=0`이면 0% 대신 N/A다.

| 지표 | 식 | 목적 |
|---|---|---|
| **완전 일치 판독률 (Exact Decode Rate, EDR)** | `C / N` | 해당 평가 집합에서 정확히 읽은 비율 |
| **오독률 (False Decode Rate, FDR)** | `W / N` | 전체 시도 중 틀린 값을 내보낸 비율 |
| 무응답률 (No-return Rate, NRR) | `U / N` | 값을 반환하지 못한 비율 |
| 출력 중 오독 비율 (보조) | `W / (C+W)` | 반환된 값의 신뢰성. FDR와 분모가 다르며 미출력 시 N/A |
| 전체 실패율 (보조) | `(W+U) / N` | 오독과 무응답을 합친 실패 |

### 난인식 구제율의 분모를 두 가지로 구분한다

**주지표 RR_H (정답 판정상 난인식 구제율)**:

```text
H = {i : D0(i)가 GT(i)와 완전 일치하지 않음}  # D0의 오독과 무응답 모두 포함
RR_H = H에서 DM이 정답인 수 / |H|
FDR_H = H에서 DM이 오독인 수 / |H|
```

H는 **모델 실행 전에 같은 D0로 한 번 고정**한다. 모델별 성공 여부나 GT 보정
성공 여부로 H를 재선별하지 않는다. 실제 운영에서는 D0의 오독을 GT로 알아낼 수
없으므로, 이 지표를 “현장에서 Stage 2가 호출되는 비율”로 해석하지 않는다.

**운영 보조지표 RR_U (무응답 구제율)**:

```text
H_U = {i : D0(i)가 값을 반환하지 않음}
RR_U = H_U에서 실제 통합 파이프라인이 정답을 반환한 수 / |H_U|
```

실제 경로가 D0 무응답에서만 Stage 2를 호출하면 RR_U가 그 호출 대상의 성능이다.
H에 포함된 1차 오독은 조기 종료되어 그대로 오독일 수 있다. 이 차이를 숨기지 않는다.

이미 발행된 target 1,500장은 **고정 벤치마크 B**다. 과거 선별 디코더와 설정으로
정답 실패·GT 보정 성공 조건을 거친 표본이며 현장 분포를 대표하지 않는다.
이 집합의 결과는 `EDR_B=C_B/1500`로 우선 표기한다. 동일 실행의 D0를 다시
채점하여 B 전부가 H인 것을 확인한 때에만 EDR_B를 RR_H라고 함께 표기한다.
그렇지 않으면 EDR_B와 B 안의 RR_H를 별도로 보고하고 기존 1,500장을 몰래 바꾸지 않는다.

### 개선량과 오독 처리

- `ΔRR_H = RR_H(개선안) − RR_H(ResNet 기준선)`, 단위는 **%p**다.
- 항등 필드 대비 개선도 별도로 기록한다. 항등 필드는 출력 크기에 따라
  리샘플링 효과가 있으므로 구제율이 0%라고 가정하지 않는다.
- D0와 DM의 C/W/U 전이표를 저장해 `U→W`, `W→W`, `W→C` 등을 센다.
  오독 ID가 겹친다는 사실만으로 “물려받은 오독”이라는 인과를 확정하지 않는다.
- 오독 0건은 설계 목표로 유지한다. 관측 0건을 오독 가능성이 없다는 증거로
  쓰지 않는다. 체크섬의 단순 확률을 실제 오독률이나 허용 기준으로 쓰지 않는다.
- 연구 후보가 0건을 달성하지 못해도 결과는 그대로 보고한다. 기준선 대비 낮은
  오독률만으로 배포 안전성이 확보됐다고 선언하지 않는다.

## 4. 좌표 진단: 48점 EPE로 통일

원본 입력 crop 크기를 `W_i × H_i`, 각 정규화 제어점 오차를 `dx, dy`라 한다.
리사이즈 입력 크기 384×160이나 출력 캔버스 크기로 환산하지 않는다.

```text
ex[i,j] = (pred_x[i,j] - gt_x[i,j]) × (W_i - 1)
ey[i,j] = (pred_y[i,j] - gt_y[i,j]) × (H_i - 1)
e[i,j]  = sqrt(ex[i,j]^2 + ey[i,j]^2)       # 점별 EPE, px
M       = N_geometry × 48

EPE_mean = sum(e) / M
EPE_RMSE = sqrt(sum(e^2) / M)
EPE_P95  = Q0.95(all M values of e)
MAE_x    = sum(abs(ex)) / M
MAE_y    = sum(abs(ey)) / M
```

**필수 보고**는 EPE mean/P95, MAE_x/MAE_y이며 RMSE는 상세표에 함께 저장한다.
모든 점을 모은 후 집계한다. 배치별 평균·RMSE·P95를 단순 평균하지 않는다.
v1에서 점 수는 항상 48이므로 이미지와 점의 가중치가 일정하다.

분위수는 오름차순 배열 `a`에 대해 `h=(M−1)q`,
`k=floor(h)`, `t=h−k`일 때 `(1−t)a[k]+t a[min(k+1,M−1)]`의
선형 보간으로 고정한다. EPE와 지연시간 모두 같은 분위수 규칙을 쓴다.

합성 GT가 있는 모든 지정 샘플에서, 디코딩 성공·실패와 무관하게 측정한다.
유한한 범위 밖 예측도 평가 전 임의로 clamp하지 않는다. NaN/Inf·잘못된 shape는
`invalid_field_count`로 기록하고, 그 실행의 전체 좌표 지표는 N/A로 표시한다.
유효 샘플만 계산한 진단값은 분모를 밝혀 별도 표기하며 전체 모델 성적으로 쓰지 않는다.
실촬영에 제어점 GT가 없으면 좌표 지표는 N/A다.

계산 확인 예: 한 점의 x/y 오차가 3px/4px이면 EPE는 **5px**다. 축별 절대오차
평균 3.5px와 다르다. 점별 EPE가 [0, 0, 0, 10]이면 위 선형 보간의 P95는
**8.5px**다. 이를 배치로 나누어 P95를 평균한 값으로 대체하지 않는다.

보조 진단으로 원시 예측 각 행의 인접 x 좌표에 대해
`x[j+1] <= x[j]`인 쌍의 비율을 기록한다. 분모는 `N_geometry × 3 × 15`다.
이를 단조성 위반률이라고 부르되, 0%가 TPS 전체 영역의 무접힘을 보장하지는 않는다.

> EPE는 좌표 정확도의 진단 지표다. “EPE P95 4px 이상이면 구조 실패”나
> 임의의 Rayleigh 환산값을 합격 기준으로 사용하지 않는다.

## 5. 평가 경로: oracle 성적과 통합 성적을 분리

| 경로 | 실행 | 알 수 있는 것 / 보고 방식 |
|---|---|---|
| **좌표 단독** | 고정 crop → Stage 2 | 합성 GT와 EPE 비교. 디코더 불필요 |
| **Oracle 진단** | 고정 crop → Stage 2 → 전체 격자 TPS → 고정 디코더, GT `h_flat,w_flat` 사용 | 기하 예측 진단. **GT 캔버스를 사용한 비배포 실험**이라고 명시 |
| **실전 crop 경로** | 고정 crop → Stage 2 → 통합 Stage 3·4 | 입력 crop과 예측만 사용. 출력 크기·TPS 축소·재시도 정책 고정 |
| **전체 E2E** | 원본 사진 → Stage 1 → D0 → 실제 조기 종료/Stage 2·3·4 | 실제 호출 정책을 반영한 EDR/FDR/NRR, RR_H/RR_U 및 E2E 지연 |

Stage 2 비교에서는 동일한 crop에 모든 후보를 강제 실행한다. D0의 1차 오독까지
Stage 2로 보낼 수 있는 **오프라인 비교**이며, E2E 성능으로 발표하지 않는다.
반대로 E2E에서는 GT를 보고 1차 오독만 다시 보내는 동작을 허용하지 않는다.

기준선은 **ResNet18-C3**, **보정 전 D0**, **항등 필드**를 필수로 둔다.
**GT 48점**과 **GT 4점 호모그래피**는 정답을 쓰는 진단 참조다. 후자는 배포 가능한
4점 추정 모델의 결과가 아니다. GT 48점도 GT 캔버스/전체 TPS 경로에서의 참조 성적과
실전 crop 경로에서의 성적을 구분하며, 모든 설정에서 100%라고 가정하지 않는다.

실전 경로의 출력 크기·TPS 축소율·디코더·재시도 횟수/순서는 강민/SW의 1차 구현과
맞춘 **실행 설정 파일과 hash**로 고정한다. 아직 구현되지 않은 설정은 `미정`으로
기록하고 그 경로의 성적을 비워 둔다. 이 문서가 성능을 재거나 운영 코드를 바꾼 것은 아니다.
관련 조건은 [Stage 2 인계 규격](../stage2-handoff.md)과
[Stage 3 구현 가이드](../stage3-rectify-guide.md)를 따른다.

## 6. 데이터 분리와 실험 고정 조건

| 집합 | 용도 | 금지 사항 |
|---|---|---|
| train | 가중치 학습, 필요한 변형 데이터 추가 | validation/eval 샘플을 다시 넣기 |
| validation 전체 + 그 안의 고정 H | checkpoint·loss·학습률·증강·재시도 설정 선택 | 후보마다 유리한 검증 ID 재선택 |
| 기존 synthetic/v1 eval 1,500 | 기존 실험 재현·동일 설정 회귀 비교 | 이미 여러 설계에 활용된 결과를 완전히 손대지 않은 최종 test라 주장하기 |
| 새 합성 holdout / 실촬영 eval | 설정 잠금 후 최종 평가 | 결과를 보고 설정을 바꾼 뒤 같은 표본을 새 최종 평가로 재사용하기 |

기존 1,500장은 이미 모델 보고서와 캔버스/재시도 설계에 활용됐다. 후속 개선을 이
집합에서 선택했다면 개발 벤치마크로 명시하고 **새 holdout 또는 잠근 실촬영 eval**
에서 결론을 확인한다. 합성과 실촬영 점수는 합산하지 않는다.

비교 실험마다 아래를 잠근다.

- 데이터 revision, sample ID, group ID, split manifest와 SHA-256, GT/PNG/NPZ 생성 버전.
- Code128, 입력 전처리, 16×3 좌표 계약, Stage 1 crop 버전 또는 동일 저장 crop.
- 출력 캔버스, TPS 구현·축소율, 보간·경계 처리, decoder 버전·옵션, 재시도·선택 정책.
- 코드 commit, checkpoint SHA-256, seed, 학습 설정, 평가 경로, 기계·정밀도·스레드 수.
- loss·학습률 등의 실험은 한 번에 한 요인을 바꾼다. 변경한 요인은 설정 차이로 남긴다.
- 실험 초기에는 seed 42로 탐색하고, 보고서 핵심 개선안은 동일 split에서
  학습 seed 42/43/44로 기준선과 함께 확인한다. 3회 미실행은 `단일 seed`라고 표시한다.

validation checkpoint 선택은 **같은 실전 crop 경로의 RR_H 최대 → 동률이면
FDR_H 최소 → EPE_mean 최소 → 더 이른 epoch** 순으로 고정한다.
실전 경로가 없을 때는 EPE_mean 최소로 임시 선택하고 `geometry_only_selection`으로
표시한다. 기존 `best.pt`는 val loss 기준으로 선택됐다는 이력을 유지한다.
고오독 후보는 아래 채택 기준을 별도로 통과해야 한다.

low/mid/high는 데이터의 기존 bucket 라벨이며 자동으로 난이도 순서라고 가정하지
않는다. 각 bucket 및 `target/hard/first_ok`별 표본 수와 성적을 보고한다.
곡률·반사·복합 훼손별 표도 GT 메타데이터가 있을 때 추가한다.

## 7. 지연시간과 모델 비용

- **Stage 2 지연**: 메모리의 원본 crop → 전처리 → 모델 실행 → CPU의 GeometryField 완성.
  GPU 전송·동기화·출력 변환을 포함한다. TPS/디코더·디스크 읽기·모델 초기 로딩은 제외한다.
- **E2E 지연**: 메모리의 원본 BGR 사진 → 최종 판독 결과. Stage 1, D0,
  조기 종료, 모든 실제 재시도를 포함한다. HTTP 전송·UI·디스크 입출력은 별도다.
- 배치 1, eval 모드, gradient 비활성화, 후보별 동일 기계·정밀도로 **단독 실행**한다.
  CPU 비교 기준은 1 thread이며 다른 배포 thread 설정은 별도 행으로 기록한다.
- timing용 고정 sample 목록 순서대로 50회 warm-up 후, 전체 목록을 3회 측정한다.
  각 회차의 p50/p95를 보고하고 대표값은 **3개 p50의 중앙값 / 3개 p95의 중앙값**이다.
  3×N을 독립 평가 표본 수로 세지 않는다. 목록 크기 N과 모든 원시 시간을 보관한다.
- CUDA 작업은 시작/종료 경계에서 동기화한다. 실패·무응답 시간도 포함한다.
  모델 초기 로딩 시간은 별도 보고하고 정상 추론 p95와 섞지 않는다.
- Stage 2 p95 **150ms**, E2E p95 **500ms**는 기존 설계 예산으로 보고한다.
  기준 기계가 미정이면 측정 기계를 명시하고 현장 예산 충족으로 확대 해석하지 않는다.
- 총 parameter 수, 추론용 가중치 MiB(`bytes/2^20`), 가능하면 메모리 측정법과
  peak 사용량을 기록한다. optimizer를 포함한 학습 checkpoint 용량과 구분한다.

## 8. 신뢰구간과 개선안 채택

EDR, FDR, RR_H, RR_U에는 **분자/분모 + 95% Wilson 구간**을 함께 쓴다.
`p=k/n, z=1.96`이면 아래를 사용한다.

```text
den    = 1 + z^2/n
center = (p + z^2/(2n)) / den
half   = z/den × sqrt(p(1-p)/n + z^2/(4n^2))
CI     = [max(0, center-half), min(1, center+half)]
```

서로 연관된 동일 송장·원본의 여러 샘플에는 단순 Wilson 구간의 독립 가정이
맞지 않을 수 있다. 이때 `group_id` 단위 bootstrap을 사용하고 그 방법을 밝힌다.
독립 여부가 미확인인 과거 보고값에는 참고 구간이라는 한계를 붙인다.

모델 간 ΔRR_H의 구간은 동일 sample ID를 짝지어 bootstrap 10,000회, seed 42,
2.5/97.5 백분위로 계산한다. 그룹이 있으면 그룹째 재표집하고 각 표본에서
분자·분모를 다시 합산한다. H가 빈 재표집의 비율도 기록하며 유효 재표집이
10,000개 미만이면 구간을 확정값으로 발표하지 않는다.
학습 seed 반복 변동(mean±sample SD)은 이 표본 신뢰구간과 별도로 보고한다.

채택 순서는 다음과 같다.

1. 동일 데이터·경로·설정의 유효한 실행인지 확인한다.
2. 오독 건수가 기준선보다 늘면 구제율 증가만으로 자동 채택하지 않는다.
   샘플별 전이와 원인을 검토하고 팀 판단을 기록한다. 통계적 비열등성을 입증했다는 뜻은 아니다.
3. RR_H 개선량과 불확실성을 보고한다. 작은 차이의 구간이 0을 포함하면
   “우월성이 확정됐다”고 하지 않는다. 좌표 EPE만 좋아진 것도 구제율 개선으로 부르지 않는다.
4. 실전 경로의 지연 예산과 모델 비용을 확인한다. 연구 후보 채택과 현장 배포 승인은 구분한다.

서로 다른 데이터·경로는 표를 나눈다. 각 표 제목에 dataset/split/N, 경로,

| 모델/변경 | C/W/U | EDR (%) | RR_H (%)·95% CI·분모 | ΔRR_H (%p) | FDR_H (%) | EPE mean/P95 (px) | x/y MAE (px) | Stage 2 p50/p95 (ms) |
|---|---|---|---|---|---|---|---|---|
| ResNet18-C3 기준선 | 미측정 | 미측정 | 미측정 | 기준 | 미측정 | v1 재집계 필요 | 미측정 | 미측정 |
| 개선안: 변경 1개 명시 | 미측정 | 미측정 | 미측정 | 미측정 | 미측정 | 미측정 | 미측정 | 미측정 |

E2E 표에는 전체 EDR/FDR/NRR, D0의 정답률과 **실제 조기 종료율**,
RR_H/RR_U와 각 분모, E2E p50/p95를 넣는다. 조기 종료는 오독에도 일어날 수
있으므로 정답률과 동일하게 취급하지 않는다. 재시도별 누적 정답·오독·추가 지연도
기록하며, GT로 성공할 때까지 실행한 합집합은 `oracle retry ceiling`으로만 표기한다.

각 실행은 아래를 보관한다. 공개 실촬영 데이터에 개인정보가 있으면 정답 payload는
승인된 저장소에 두고 공개 표에는 비식별 ID와 집계만 둔다.

- `run_config`: 위 고정 조건, protocol version, source commit, checkpoint/dataset hash.
- `per_sample`: ID/group/bucket/band, GT, D0·DM·각 시도 반환값, C/W/U,
  오류 이유, 실제 시도 횟수, 단계별 시간.
- `geometry`: ID, 원본 W/H, 원시 예측/GT 48×2 좌표. 집계만으로 EPE를 복원하지 않는다.
- `summary`: 전체·H·H_U·bucket별 분자/분모, 지표·CI, invalid 수, 비교 기준선.
- `timing`: warm-up 제외 원시 시간과 3회 결과, 장치/버전/thread/정밀도.

발표 문장 예시:

> 고정 난인식 집합 N장에서 ResNet 기준선 대비 정답 구제율이 A%에서 B%로
> Δ%p 변했다. 오독은 W0건에서 W1건, Stage 2 p95는 T0ms에서 T1ms였다.
> 이 결과는 [합성/실촬영], [oracle/실전 crop/E2E] 경로이며 95% 구간은 […]이다.

## 10. 기존 결과에 적용할 정정

1. ResNet 보고서의 **mean 1.3723 / RMSE 2.7068 / P95 3.7989px**는

## 문제 1. SSIM은 실촬영 데이터에서 측정할 수 없다

이건 의견 문제가 아니라 **물리적 제약**이다.

- 기획서 4.6.1: SSIM을 "복원 이미지와 원본(GT) 간 구조적 일치도"로 정의
  → **2026-08-04부터 SSIM은 주지표가 아니다.** 이미지를 생성하지 않으므로 이미지 품질 지표가 의미를 잃었다. 주지표는 보정 후 디코딩 성공률이다 (`0003` 참고)
- 기획서 4.6.2: "합성 데이터가 아닌 실촬영 데이터**만으로** 최종 평가"

그런데 **구겨진 비닐 사진에 대응하는 픽셀 정렬된 평탄한 정답 이미지가 물리적으로 존재하지 않는다.** 같은 송장을 펴서 다시 촬영해도 픽셀이 정렬되지 않는다.

→ SSIM은 **합성 검증셋 전용**이다. 실촬영셋에서 측정 가능한 것은 디코딩 성공률과 지연시간뿐이다.

## 문제 2. 최종 KPI의 분모 정의가 베이스라인 비교를 무의미하게 만든다

기획서 4.6.1은 최종 KPI를 **"pyzbar 단독 실패 샘플 대상, 파이프라인 통과 후 성공률 90% 이상"**으로 정의한다.

이 정의면 4.6.2의 3조건 비교에서 **조건(1) pyzbar 단독의 성공률이 정의상 0%**가 되어 비교가 성립하지 않는다.

또한 "실패한 것 중 90%를 살린다"는 상당히 야심찬 수치다. 참고로 [Nature Sci Rep 2025 논문](https://www.nature.com/articles/s41598-025-29720-w)의 부분 가림 조건 디코딩 정확도가 78.3%다.

### 제안: 지표를 셋으로 분리한다

| 지표 | 정의 | 의미 |
|---|---|---|
| **종합 디코딩률** | 전체 테스트셋 중 정답 일치 비율 | 시스템 전체 성능 |
| **난인식 구제율** | 디코더 단독 실패 샘플 중 파이프라인이 살린 비율 | AI의 기여도 |
| **오독률** | 틀린 번호를 출력한 비율 | **0%여야 한다** |

오독률을 별도로 두는 이유: 물류에서는 **틀린 번호를 자신 있게 내놓는 것이 못 읽는 것보다 나쁘다.** 잘못된 화물 정보가 그대로 흘러간다. 기획서 4.6.2의 "완전 일치 판정" 원칙을 지표로 승격한 것이다.

### 현장 언어로는

실무에서 의미 있는 표현은 이쪽이다.

> **노리드율 N% → M% 이하**

기획서에는 이 지표가 없다. 추가를 검토한다.

## 문제 3. mAP 0.95 목표의 근거와 지표 선택

기획서는 mAP 0.95 이상을 목표로 하지만 근거가 제시되지 않았다. 위 논문이 창고 환경 YOLOv8로 **mAP@0.5 92.4%**, mAP@0.5:0.95 64.5%다. 952장 + 자체 라벨로 0.95는 낙관적이다.

또한 **mAP@0.5만으로는 불충분하다.** OBB에서는 각도 오차가 크롭 품질을 직접 좌우하는데, IoU 0.5 기준은 각도가 어긋나도 통과한다. 크롭이 비뚤면 디코더가 못 읽는다.

### 제안

- **mAP@0.5:0.95**와 **각도 오차(°)**를 함께 사용
- 구체적 목표 수치는 `0004`의 데이터 실태 파악 후 확정
