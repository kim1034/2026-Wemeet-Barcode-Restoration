## 입력 전처리 (2026-08-04 추가)

입력은 `DetectedBarcode.crop_bgr_uint8` — **이미지**다. 출력만 숫자다.
크롭은 매번 크기가 다르므로 고정 크기로 맞춰야 하는데, 방법에 따라 좌표 처리가 달라진다.

| 항목 | 후보 | 정해야 하는 이유 |
|---|---|---|
| **크기 맞추기** | 강제 리사이즈 (종횡비 무시) / letterbox 패딩 | letterbox 를 쓰면 모델 출력이 **패딩된 이미지 기준**이 되어 원본 크롭 기준으로 환산해야 한다. 안 하면 위아래로 밀린 채 펴진다 |
| **입력 해상도** | 128 / 256 / 384 | §8.4 의 "모듈 2px 이상" 조건과 맞물린다. 너무 줄이면 얇은 바가 사라져 곡률을 추정할 근거가 없어진다 |
| **채널 수** | BGR 3채널 / 흑백 1채널 | 바코드는 색 정보가 무의미하다. 1채널이면 가볍다. 계약은 3채널을 주므로 모델 내부에서 변환한다 |

**v1 제안은 강제 리사이즈 + 흑백 1채널 + `H=160, W=384`이다.** 1채널을
3채널로 repeat한 뒤 ImageNet pretrained 백본에 넣는다. 정규화 좌표는 리사이즈에
불변이므로 강제 리사이즈가 가장 단순하다. `256×256` 대 `160×384`는 백본 비교와
분리한 ablation으로 검증하며, 종횡비 왜곡이 성능에 걸리는 것이 확인되면 letterbox를
실험한다.

**입력 해상도를 바꾼 실험은 반드시 W&B 에 기록할 것.** 해상도가 곧 추론 시간이고, 150ms 예산에 직접 영향한다.

## 후보

| 후보 | 출력 | 장점 | 위험 |
|---|---|---|---|
| **제어점 회귀 + TPS** (기본안) | **16×3=48점** × 2좌표 = 숫자 96개 (2026-09-14 확정) | 매끄러움이 구조적으로 보장돼 **픽셀이 찢어지지 않는다.** 출력이 작아 학습이 쉽다 | 급격한 주름(fold) 표현에 한계 |
| Dense flow map | (H, W, 2) | 주름까지 표현 가능 | smoothness 정규화 필요. 노이즈 시 픽셀이 찢어진다 |
| **4점 호모그래피** | 숫자 8개 | 가장 단순. **베이스라인으로 반드시 측정** | 평면 왜곡만. 원통 곡률은 못 다룬다 |

**진행 순서**: 4점 호모그래피로 베이스라인을 만들고, 제어점 회귀를 학습해 비교한다. 주름이 문제로 드러나면 dense flow를 실험한다.

**백본 (2026-09-15 설계 기준)**: `ResNet18-C3`를 Stage 2 v1 구현 기준으로
삼는다. 여기서 `ResNet18-C3`는 공식 모델명이 아니라 ImageNet pretrained ResNet18의
`layer3`까지만 사용하는 편의상 이름이다. MobileNetV3-Small과 EfficientNet-B0를
동일 조건에서 비교하며, 최종 배포 백본은 실험 후 재확인한다. 상세한 extraction
stage·channel과 fair comparison protocol은 [Stage 2 백본 비교 설계](../experiments/2026-09-15-stage2-backbone/README.md)에 기록한다.

## 사전 실험으로 이미 정해진 것

설계 문서 §8의 실측 결과다. 후보 비교의 출발점이다.

| 확인한 것 | 결과 |
|---|---|
| 필요한 제어점 개수 | **4×2=8점이면 가로 압축 35~70°가 복원된다** |
| 필요한 정확도 | 제어점 오차 **8px까지 판독 성공** (모듈 폭 5.5px) |
| 복원 불가 경계 | 가장자리 모듈이 **1px 이하로 압축되면 불가** (84° 이상) |
| 무해한 왜곡 | **수직 방향 휘어짐은 디코딩을 깨지 않는다** (진폭 32px까지) |

**정확도가 병목이 아니다**는 것이 중요하다. 픽셀 단위 정밀도를 목표로 잡지 말 것. 다만 위 수치는 합성·무노이즈·무반사 조건의 **낙관적 상한**이다.

### 2026-08-28 재측정 정정

[합성 스파이크](../experiments/2026-08-28-synthesis-spike/README.md)에서 위 표 두 줄이 정정됐다.

| 위 표의 항목 | 정정 |
|---|---|
| "4×2=8점이면 35~70°가 복원된다" | 맞다. 단 **원통(저주파)에 한해서다.** 원통은 `n_x=2` 에서까지 읽힌다. 제어점 개수가 정하는 것은 **표현 가능한 최소 파장**이고, 나이키스트 `λ ≥ 2W/(n_x−1)` 와 실측이 맞는다 — 4점이면 0.67W, 6점이면 0.40W |
| "복원 불가 경계: 모듈 1px 이하" | **0.8px 까지 복원된다.** 2px 기준은 2배 이상 보수적이다. 다만 무노이즈 조건의 상한이므로 안전 마진으로 유지하되 파라미터로 둔다 |
| — (신설) | **병목은 세로가 아니라 가로다.** 굽이치는 능선을 `λ_y` 0.5H~4H 로 흔들어도 `n_y=2` 에서까지 전부 읽혔다 |

**격자 권고: 4×3 → 6×3.** 모델 출력이 24개에서 36개 숫자로 늘어난다.
`schemas.py` 는 "최소 4개"만 요구하므로 코드 변경은 없다. SW 의 20ms 예산에는
TPS 선형 시스템이 12³ → 18³ 으로 커지는 만큼 영향이 있어 실측이 필요하다.

> **다만 이 권고의 근거는 아직 약하다.** 랜덤 분포에서 "Stage 2 가 값을 하는 샘플" 비율이
> `n_x` = 4 / 6 / 8 에서 14% / 12% / 15% 로 **차이가 없었다**(N=120, ±3%p).
> 짧은 파장 샘플이 드물기 때문이다. 6×3 이 값을 하려면 현장에 짧은 파장 주름이
> 실제로 흔해야 한다 — `0001` 현장 확인 항목이다. **후보 비교 실험에서 `n_x` 도 같이 흔들 것.**

### 2026-09-14 확정 — 제어점 격자는 `16 × 3 = 48점` 이다

위 6×3 권고는 **폐기한다.** [제어점 개수 실험](../experiments/2026-09-09-control-points/README.md)에서
24개 격자를 전수 측정했다.

| | |
|---|---|
| **확정값** | **`n_x × n_y = 16 × 3 = 48점`** (모델 출력 숫자 96개) |
| 코드 | `wemeet/data/synthesis.py` 의 `N_X, N_Y = 16, 3` |
| `schemas.py` | **변경 없음** — 계약은 "최소 4개"만 요구한다 |
| **`n_y = 3` 재검증** | **필요함** — 아래 참고. `n_x = 16` 은 영향 없다 |

> **`n_y = 3` 과 `G` 세로 해상도 `n_v = 33` 은 재검증 대상이다 (2026-09-14).**
> 위 실험은 `H_OBS = 220` 고정 높이로 돌았는데, 종횡비를 `U(2.0, 2.3)` 에서
> 뽑도록 바꾸면 크롭이 세로로 커져 세로 대응장 변동이 늘어난다.
>
> | 버킷 | H_OBS=220 (중앙/95%) | 종횡비 유도 (중앙/95%) | 변화 |
> |---|---|---|---|
> | `H` | 20.30 / 64.55 px | **27.56 / 77.35 px** | **+36%** |
>
> 가로 나이키스트는 `w` 기준이라 `n_x = 16` 은 그대로다. 재검증은 되돌릴 수
> 있어서 후속 작업이다 — 제어점은 레시피에 저장되지 않고 `build()` 가 매번 계산하므로,
> `n_y`·`n_v` 가 바뀜도 **평가 세트는 PNG 를 그대로 두고 NPZ 만 다시 구우면 된다.**

**왜 바뀌었나.** 지난 근거가 무효였던 이유가 둘이다.

| | |
|---|---|
| **표본 정의가 순환했다** | 기존 구간 라벨이 정답 제어점으로 rectify 해서 판정하므로 "목표 구간"의 정의 자체가 `n_x` 에 의존했다. 이번 실험은 **밀집 대응장 `G` 로 직접 remap 한 것**을 복원 상한으로 삼아 표본을 `n_x` 와 무관하게 고정했다 |
| **상한 항이 0 이었다** | 지금까지 전부 정답 제어점(오차 0)으로 돌렸다. 제어점이 촘촘해지면 같은 좌표 오차가 더 급한 왜곡을 만드는데, 오차를 안 넣으면 이 항이 영영 안 보인다 |

**최적 격자는 모델의 좌표 오차 σ 의 함수다.** σ=0 이면 16×7, σ=1 이면 16×5,
σ=2 면 16×3, σ=4 면 10×3 이 최선이다. σ 는 **이 결정(0003)이 모델을 학습해야 나오는 값**이라
미측정이다. 그래서 **최대 후회(minimax regret)** 로 골랐다.

| 격자 | 점 | 비용(환산) | 20ms | **최대 후회** | σ=0 | σ=1 | σ=2 | σ=4 |
|---|---|---|---|---|---|---|---|---|
| **16×3 (확정)** | **48** | **23.3 ms** | **✗** | **10.2** | 75.6 | 65.8 | **59.1** | 42.4 |
| 12×3 (예산 내 최선) | 36 | 18.4 ms | ✓ | 15.4 | 70.3 | 63.2 | 57.4 | 46.8 |
| 8×5 | 40 | 19.6 ms | ✓ | 21.7 | 64.1 | 56.0 | 53.8 | 43.8 |
| 6×3 (구 권고) | 18 | 9.6 ms | ✓ | 30.8 | 55.0 | 50.6 | 48.4 | 44.5 |
| 16×7 | 112 | 56.5 ms | ✗ | 35.2 | **85.8** | 65.5 | 45.4 | 14.3 |

**`n_y` 를 3 에서 멈추는 이유.** `n_y` 도 `n_x` 와 똑같이 σ 에 대해 뒤집힌다.
`16×7` 은 σ=0 에서 85.8% 로 전체 1위인데 σ=4 에서 **14.3%** 로 무너진다 —
세로로 점이 촘촘해지면 점당 좌표 오차가 보간을 지배한다. TPS++(IJCAI 2023)가
보고한 "8×16 이 4×16 보다 나쁘다"는 세로 상한이 우리 조건에서도 재현됐다.

**현행 6×3 이 남기던 헤드룸.** `G` 로 복원 가능한 표본 중 6×3 이 실제로 읽는 것은
L 70.8% / M 51.8% / **H 42.5%** 였다 — `H` 에서 복원 가능한 것의 58% 를 놓치고 있었다.

**속도는 후순위로 두고 정확도를 우선한다는 방침으로 정한 값이다.** 애초에 이 순위는
비용을 빼고 정확도만으로 매긴 것이라, 속도를 고려에서 빼도 답은 `16×3` 그대로다.

`warp` 단계가 20 ms → 23.3 ms (실측 평균 크롭)가 되지만 `architecture.md` 의
**여유 30 ms** 에서 흡수된다 — 평균 크롭에서 여유의 11%, 가장 넓은 가정(784px,
32.8 ms)에서도 43% 다. 예산표를 `warp` 24 ms / 여유 26 ms 로 갱신했다.
**SW파트가 따로 결정할 것은 없다.** 되돌려야 한다면 대안은 `12×3`(18.4 ms, 최대 후회 15.4)이다.
상세: [2단계 → 3단계 인계 규격](../stage2-handoff.md#제어점-개수--확정-16--3--48점)

**재확인 트리거.** 아래가 바뀌면 이 값을 다시 정해야 한다. 표본별 행이 전부 남아 있어
대부분은 재실행이 아니라 **재가중**이면 된다.

| 트리거 | |
|---|---|
| **σ 실측** | 이 결정이 모델을 학습해 좌표 오차를 재면, 실험의 표에서 **그 σ 의 행을 읽으면 된다.** 재실행 불필요 |
| **`0006` 디코더** | `decode()` 가 zxing-cpp 하드코딩이다. 바뀌면 표본 집합 자체가 다시 뽑힌다 |
| **`d_t` 분포** | `d_t ~ U(1.3, 2.6)` 를 버킷과 독립으로 뽑는 가정 위에 있다 |
| **20ms 예산 / 기준 기계** | 예산이 안 늘면 12×3 으로 후퇴한다 |

## 손실 함수

좌표 회귀이므로 단순하다.

| 항목 | 역할 | 초기 가중치 |
|---|---|---|
| **L1 / Smooth L1** | 제어점 좌표 오차 | 1.0 |
| (선택) 재투영 손실 | 추정한 필드로 실제로 펴서 정답 이미지와 비교 | 0.0 → 실험 |

**기존 방식에서 필요했던 SSIM·엣지 손실이 필요 없다.** 이미지를 만들지 않으므로 "흐릿해서 못 읽는" 문제 자체가 없다.

재투영 손실은 L1만으로 부족할 때 추가한다. 판독 가능성과 더 직접 연결되지만 학습이 무거워진다.

## 비교 기준

| 기준 | 목표 | 측정 대상 |
|---|---|---|
| **보정 후 디코딩 성공률** (주지표) | `0005`에서 확정 | 실촬영 `dev` + 합성 검증셋 |
| 제어점 좌표 오차 (px, 평균/최대) | 실험으로 정함 | **합성 검증셋 전용** |
| **추론 시간 (ms)** | **150ms 이하** | 전체 500ms 중 배정분 |
| 조기 종료 비율 | 기록만 | 실촬영 `dev` |

**주지표가 SSIM에서 디코딩 성공률로 바뀌었다.** 이미지를 만들지 않으므로 이미지 품질 지표가 의미가 없다. 최종 목표는 처음부터 "기계가 읽는 것"이었고, 이제 지표가 그것과 직접 일치한다.

**제어점 좌표 오차는 합성 데이터에서만 측정할 수 있다.** 실촬영에는 정답 제어점이 없다.

### 조기 종료 비율을 꼭 기록할 것

1차 디코딩(보정 없이)에서 성공하는 비율이다. 이 값이 높으면 **기하 추정이 실제로 필요한 경우가 적다**는 뜻이므로 모델을 무겁게 만들 이유가 없다. 사전 실험에서 수직 왜곡이 무해함을 확인했으니 예상보다 높을 수 있다.

**2026-08-28 실측: 예상보다 훨씬 높다.** 합성 기준 조기 종료가 모듈 폭 2.8~4.0px 에서 **75%**,
1.6~2.2px 에서 48%다. 모듈이 5.5px 이면 원통 70°까지 보정 없이 읽힌다.

### 평가 세트는 목표 구간에 집중시켜야 한다 (2026-08-28 신설)

후보 모델을 비교하는 것이 이 결정의 목적이므로, **평가 세트 구성이 결과를 좌우한다.**

| 구간 | 1차 | 보정 후 | 모델 비교에서 |
|---|---|---|---|
| 1차 성공 | 성공 | — | **어떤 모델을 써도 결과가 같다.** 파이프라인이 Stage 2 를 부르지도 않는다 |
| 원리적 불가 | 실패 | 실패 | **어떤 모델도 실패한다** |
| **목표** | 실패 | 성공 | **여기서만 모델이 갈린다** |

평가 세트에 1차 성공 샘플이 75% 섞여 있으면 모델 A·B 의 성공률이 둘 다 80% 대로 나오고
**차이가 안 보인다.** 실제 차이는 나머지 안에 숨는다.

**평가 세트는 목표 구간 비율을 100% 에 가깝게 만든다.** 생성기가 목표 구간을 12~18% 로만
뽑으므로 5~6배 초과 생성 후 거른다. 평가 세트는 수백~수천 장이면 되고 레시피만 저장하므로
비용은 CPU 시간뿐이다.

**학습 세트도 같은 방향이다 (2026-09-08 반전).** 이전 판은 "학습은 구간 비율을 맞추지 않고
기하 분포 커버리지로 한다" 였다. 폐기했다. v1 학습 세트는 **이 결정을 내리기 위한 계측기**이지
현장 출하용이 아니고, 파이프라인이 1차 성공 구간에서 Stage 2 를 부르지 않으므로 그 샘플로
학습하는 것은 **도메인 불일치**다. 쉬운 샘플이 지배하면 제어점 회귀가 평균으로 끌려가
변위를 과소예측하고, 그러면 정확히 목표 구간에서 실패한다.

| 구간 | 학습 세트 비중 |
|---|---|
| 목표 | **50%** |
| 불가 · 기하 관측 가능 (포화 화소 비율 ≤ τ) | **35%** — 어려운 감독 신호다 |
| 1차 성공 | **15%** — 쉬운 끝의 앵커로만 |
| 불가 · 포화 소실 (> τ) | **0%** — 없는 것을 맞히라는 라벨 노이즈다 |

`d_m0` 는 세 버킷(`L` 1.6~2.5 / `M` 2.5~3.7 / `H` 3.7~6.0 px)으로 층화하고 **버킷마다** 이
비중을 맞춘다. 범위를 좁히지 않는 이유는 학습 분포가 평가 3 벌을 덮어야 하기 때문이다 —
좁히면 `eval/high` 성적이 모델 차이가 아니라 분포 불일치가 된다.

**구간 경계가 디코더(`0006`)에 종속되는 문제는 남는다.** 레시피에 구간 라벨과 포화 화소
비율을 같이 저장해서, `0006` 이 바뀌면 **재라벨링만** 하고 레시피는 재생성하지 않는다.

**이 구성은 후보 비교에서 상수로 고정한다.** 구성 자체를 축으로 흔드는 것은 후보가 좁혀진
뒤로 미룬다. 근거와 생성 비용은 [합성 설계 §7](../superpowers/specs/2026-08-28-synthesis-design.md).

### 2026-09-15 백본 비교 계획

위 표는 기하 표현 후보의 결과 표다. 백본 비교는 `ResNet18-C3`·`MobileNetV3-Small`·

## 폐기된 이전 내용 (2026-07-30 ~ 2026-08-04)

기록으로 남긴다. 11월 보고서에서 "왜 생성 복원을 쓰지 않았나"에 답할 근거다.

**후보였던 것**: U-Net(기본안) / Pix2Pix(조건부 GAN) / Restormer·NAFNet

**손실 함수 설계**: L1 1.0 + Edge·Gradient 0.5 + SSIM 0.3. "픽셀 오차만 줄이면 흐릿해지고, 흐리면 디코더가 못 읽는다"가 근거였다.

**주지표**: SSIM 0.85 (합성 검증셋 전용). 실촬영에서는 픽셀 정렬된 정답이 존재하지 않아 측정 불가라고 기록해뒀다.

**당시 적어둔 주의사항**: "SSIM이 높은데 못 읽히는 경우가 실제로 발생한다. SSIM은 대리 지표일 뿐이고 최종 목표는 기계가 읽는 것이다."

→ 새 방식에서는 이 주의사항이 **필요 없어졌다.** 주지표가 처음부터 디코딩 성공률이기 때문이다. 대리 지표를 쓰지 않게 된 것이 이 변경의 부수 이득이다.
