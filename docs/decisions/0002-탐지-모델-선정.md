## 무엇을 정하는가

`wemeet/ai/detection.py`의 `detect()`를 무엇으로 구현하는가.

## 후보

| 후보 | 라이선스 | 장점 | 단점 |
|---|---|---|---|
| **전통 영상처리** (MSER + 최소외접사각형) | 제약 없음 | 학습 불필요. 며칠이면 동작 | 배경이 복잡하면 취약 |
| **Ultralytics YOLO-OBB** | **AGPL-3.0** | 자료·예제 풍부. OBB 기본 지원 | 라이선스가 상용화 목표와 충돌 |
| **YOLOX / MMRotate** | Apache-2.0 | 라이선스 자유 | 설치·학습 난이도 높음 |

## 진행 순서

9월 1주차에 **전통 영상처리를 먼저** 구현한다. 학습이 필요 없어 빠르고, 이것이 기준선이 되면서 동시에 실제 Stage 1 구현이 된다.

그다음 YOLO-OBB로 학습해 비교한다. 라이선스가 문제가 되면 YOLOX로 전환한다.

## 조기 확정 규칙

11월 종료 일정을 지키기 위해 미리 정해둔 규칙이다 (설계 문서 §22).

전통 영상처리가 아래를 **모두** 만족하면 **YOLO 학습 단계를 건너뛰고 확정한다.**

- [ ] 실촬영 `dev` 분할에서 탐지 누락률 **5% 이하**
- [ ] 크롭 각도 오차 **5° 이하**
- [ ] 추론 시간 **100ms 이하**

건너뛰면 학습·튜닝·OBB 재라벨링이 모두 사라진다. 시간이 가장 크게 절약되는 항목이다.

**"이 단계는 딥러닝이 필요 없었다"는 결과도 보고서에 쓸 가치가 있다.** 판정 시점: 9월 3주차.

## 비교 기준

정확도만 보지 않는다. 정확해도 예산을 넘으면 탈락이고, 라이선스가 막히면 못 쓴다.

| 기준 | 목표 | 비고 |
|---|---|---|
| mAP@0.5 | `0005`에서 확정 | 기획서의 0.95는 근거 미제시 |
| mAP@0.5:0.95 | `0005`에서 확정 | OBB는 각도가 크롭 품질을 좌우하므로 필수 |
| 각도 오차 (°) | 5° 이하 | mAP@0.5만 보면 각도가 틀려도 통과한다 |
| 탐지 누락률 | 5% 이하 | |
| **추론 시간 (ms)** | **100ms 이하** | 전체 500ms 예산 중 배정분 |
| **라이선스** | 상용화 가능 여부 | 기획서 8.2의 "상용화 후보" 목표와 연결 |

참고 수치: [Nature Sci Rep 2025 논문](https://www.nature.com/articles/s41598-025-29720-w)이 창고 환경 YOLOv8로 mAP@0.5 **92.4%**, mAP@0.5:0.95 64.5%를 보고한다.
