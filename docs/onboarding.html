05

가장 헷갈리는 것

데이터는 AI에서 SW로 흐르지만, 부르는 것은 SW가 AI를 부릅니다. 두 방향이 반대입니다.

"위"가 "먼저 실행됨"을 뜻하지 않습니다. 위는 부르는 쪽, 아래는 불리는 쪽입니다. 이 방향을 어기면 서로 부르는 원이 생기고, 파이썬이 ImportError: partially initialized module을 냅니다 — 하필 통합하는 시점에 터집니다.

06

코드가 흐르는 순서

빨간 화살표가 전부 pipeline.run()에서 출발합니다. AI 코드는 불릴 때만 실행됩니다.

아래는 SW파트가 만들 코드입니다. 아직 없습니다.

# wemeet/sw/pipeline.py
from wemeet.ai.detection import detect       # ① import는 부르는 쪽에만
from wemeet.ai.geometry import estimate_geometry

def run(image_bgr):
    found = detect(image_bgr)                # ② AI 코드가 여기서 실행된다

    if not found:                            # ③ 판단은 SW가 한다
        return 실패("not_detected")
    best = max(found, key=lambda b: b.confidence)

    result = decode(흑백(best), field=None)   # ④ 먼저 읽어본다 — 여기서 끝나면 150ms
    if result.text is not None:
        return PipelineResult(...)

    field = estimate_geometry(best)           # ⑤ 숫자만 받는다. 이미지 아님
    fixed = apply_field(best, field)          # ⑥ OpenCV가 실제로 편다
    result = decode(fixed)                    # ⑦ 실패하면 ⑥부터 다시, 최대 3회
    return PipelineResult(...)                # ⑧ 중간 이미지를 버리지 않는다
  1. ③"0개면? 2개 이상이면?" 같은 판단이 한 곳에 모여 있습니다. AI로 새면 두 파트가 같은 결정을 서로 다르게 구현합니다.
  2. ④1차 디코딩을 AI가 하지 않습니다. AI가 디코더를 부르면 wemeet.sw import가 되어 규칙 위반입니다. 그리고 "먼저 읽어보고 안 되면 보정한다"는 조율 판단이라 지휘자의 일입니다.
  3. ⑤AI가 돌려주는 것은 제어점 좌표 24개입니다. 이미지가 아니므로 없는 바코드를 만들어낼 수 없습니다.
  4. ⑦재시도가 다시 펴는 것입니다. 보정이 20ms라 3번 해도 60ms입니다. 기하 추정(150ms)은 다시 돌리지 않습니다.
  5. ⑧중간 이미지를 버리면 화면에 "여기까지 펴봤다"를 못 보여줍니다. 그게 이 프로젝트가 상용 솔루션과 다른 점입니다.

덕분에 AI파트는 혼자서 실험할 수 있습니다. detect(image) 한 줄이면 되고 서버도 디코더도 필요 없습니다. 만약 AI가 SW를 알고 있었다면 탐지 실험을 하려고 FastAPI까지 끌어와야 합니다.

08

schemas.py가 하는 일

파트 사이로 흐르는 데이터의 형태를 못 박아둔 파일입니다. 여기가 있으면 서로 코드를 안 보고도 작업할 수 있습니다.

없으면 어떻게 되나

AI파트가 detect()를 만들고 SW파트가 그걸 받아 쓴다고 해봅시다. 약속이 없으면 이런 대화가 9월 내내 반복됩니다.

약속이 없을 때

"crop이 RGB예요, BGR이에요?"

"각도가 라디안인가요 도인가요?"

"못 찾으면 None 주나요 빈 리스트 주나요?"

"confidence가 0~1인가요 0~100인가요?"

→ 물어보고 답 기다리는 동안 작업이 멈춥니다. 잘못 가정하면 10월에 붙일 때 터집니다.

약속이 있을 때

crop_bgr_uint8 — 이름에 BGR이 박혀 있습니다

angle_deg_ccw — 도, 반시계

못 찾으면 빈 리스트 (문서에 적혀 있음)

0.0 <= confidence <= 1.0 — 코드가 검사합니다

→ 물어볼 게 없습니다. 파일만 열어보면 됩니다.

틀린 값을 넣으면 그 자리에서 막습니다

단순히 적어둔 문서가 아닙니다. 객체를 만드는 순간 검사합니다.

DetectedBarcode(
    crop_bgr_uint8 = crop.astype(np.float32),   # uint8 이 아니다
    angle_deg_ccw  = 0.0,
    confidence     = 1.5,                       # 범위를 넘었다
)
AssertionError   # ← 여기서 바로 터집니다

이게 좋은 겁니다. 10월에 파이프라인을 붙일 때 "왜 이미지가 이상하죠"로 이틀 쓰는 대신, 9월에 자기 코드를 돌리는 순간 알게 됩니다.

그래서 이 파일만 조심하면 됩니다

내 파트 폴더 안은 마음대로 고쳐도 됩니다. 남이 안 봅니다. 하지만 schemas.py는 양쪽이 같이 보는 파일이라 한쪽이 말없이 바꾸면 반대쪽이 전부 깨집니다.

고쳐야 할 것 같으면 먼저 상의하세요. PR을 올리기 전에 반대편 파트에게 물어보고, Issue를 만들어 decision 라벨을 붙이면 됩니다. 혼자 고쳐서 올리면 상대 파트 작업이 멈춥니다.

지금 들어 있는 것

실패했는데 이유가 없는 상태는 금지입니다. 판독에 실패했으면 failure_reason이 반드시 있어야 객체가 만들어집니다.

파이프라인은 예외를 던지지 않습니다. 어떤 상황에서도 결과를 반환합니다 — 현장에서 예외가 올라오면 서비스가 멈추고, 그게 곧 노리드 존 정체입니다.

처음 코드를 올려보기

AI파트원이 detection.py를 만들어 PR을 올리는 전 과정입니다. 다른 파트도 파일 이름만 다릅니다.

1. 최신으로 맞추고 브랜치를 만든다

git switch main
git pull                                 # 남이 올린 걸 먼저 받는다
git switch -c ai/detection-baseline      # <파트>/<하는일>

브랜치를 안 만들고 main에서 바로 작업하면 남의 작업과 섞입니다. 막아두지 않았으니 습관으로 지켜야 합니다.

2. 파일을 만들고 계약대로 반환한다

# wemeet/ai/detection.py
import numpy as np

from wemeet.schemas import DetectedBarcode      # 계약만 가져온다


def detect(image_bgr: np.ndarray) -> list[DetectedBarcode]:
    h, w = image_bgr.shape[:2]
    crop = image_bgr[int(h * 0.3):int(h * 0.7), int(w * 0.3):int(w * 0.7)]
    return [DetectedBarcode(
        crop_bgr_uint8=crop,
        angle_deg_ccw=0.0,
        confidence=0.5,
    )]

가짜 구현이어도 됩니다. 중앙을 그냥 자르는 코드지만 계약을 지키므로 파이프라인에 꽂힙니다. 나중에 진짜 모델로 바꿔 넣으면 됩니다 — pipeline.py는 건드리지 않습니다.

3. 올리기 전에 로컬에서 확인한다

uv run pytest              # 계약을 깨뜨렸는지
uv run lint-imports        # 부르면 안 되는 걸 불렀는지
uv run ruff format .       # 스타일 자동 정리
uv run ruff check --fix .

이 네 줄이 CI와 똑같은 검사입니다. 여기서 통과하면 PR도 초록입니다. 안 돌려보고 올리면 빨간 X를 본 다음에 고치게 되는데, 결과는 같고 시간만 더 걸립니다.

데이터와 가중치는 저장소에 올리지 않고 Hugging Face에 둡니다. 받기만 하는 사람은 토큰이 필요 없습니다. 올리는 사람만 발급하면 됩니다.

uv run hf auth login     # 붙여넣을 때 화면에 안 보이는 게 정상
uv run hf auth whoami    # 계정명이 나오면 성공

.env에 적어도 읽히지 않습니다 — 저장소에 .env를 읽는 코드가 없습니다. 옛 명령 huggingface-cli는 폐기됐으니 인터넷에서 본 명령은 hf로 바꿔 읽으세요.
