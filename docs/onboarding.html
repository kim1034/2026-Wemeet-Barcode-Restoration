05

가장 헷갈리는 것

데이터는 AI에서 SW로 흐르지만, 부르는 것은 SW가 AI를 부릅니다. 두 방향이 반대입니다.

"위"가 "먼저 실행됨"을 뜻하지 않습니다. 위는 부르는 쪽, 아래는 불리는 쪽입니다. 이 방향을 어기면 서로 부르는 원이 생기고, 파이썬이 ImportError: partially initialized module을 냅니다 — 하필 통합하는 시점에 터집니다.

06

코드가 흐르는 순서

빨간 화살표가 전부 pipeline.run()에서 출발합니다. AI 코드는 불릴 때만 실행됩니다.

아래는 SW파트가 만들 코드입니다. 아직 없습니다.

# wemeet/sw/pipeline.py
from wemeet.ai.detection import detect       # ① import는 부르는 쪽에만

def run(image_bgr):
    found = detect(image_bgr)                # ② AI 코드가 여기서 실행된다

    if not found:                            # ③ 판단은 SW가 한다
        return 실패("not_detected")
    best = max(found, key=lambda b: b.confidence)

    restored = restore(best)                 # ④ 하나만 넘긴다
    result   = decode(restored)              # ⑤ 재시도는 SW 몫
    return PipelineResult(...)               # ⑥ 중간 이미지를 버리지 않는다
  1. ③"0개면? 2개 이상이면?" 같은 판단이 한 곳에 모여 있습니다. AI로 새면 두 파트가 같은 결정을 서로 다르게 구현합니다.
  2. ④restore()가 리스트가 아니라 하나만 받는 이유입니다. 고르는 일은 ③에서 이미 끝났습니다.
  3. ⑥중간 이미지를 버리면 화면에 "복원된 모습"을 못 보여줍니다. 그게 이 프로젝트가 상용 솔루션과 다른 점입니다.

덕분에 AI파트는 혼자서 실험할 수 있습니다. detect(image) 한 줄이면 되고 서버도 디코더도 필요 없습니다. 만약 AI가 SW를 알고 있었다면 탐지 실험을 하려고 FastAPI까지 끌어와야 합니다.

07

규칙 하나 — 부를 수 있는 것

허용된 조합은 다섯 개뿐입니다. 어기면 CI가 막습니다.

내가부를 수 있는 것
aischemas
swschemas, ai
dataschemas, sw.decoding 만
schemas없음 — 아무것도 부르지 않습니다

확인하는 방법

uv run lint-imports

어기면 이렇게 나옵니다.

wemeet.ai is not allowed to
import wemeet.sw:
  wemeet.ai -> wemeet.sw (l.1)

외울 것은 세 줄

  1. 1AI 자기 파일에 wemeet.sw나 wemeet.data라는 글자를 쓰지 않습니다. 공용이 필요하면 wemeet.schemas를 씁니다.
  2. 2데이터 wemeet.sw.decoding까지만 쓸 수 있습니다. pipeline과 server는 안 됩니다.
  3. 3누구든 함수 안에서 import 하지 않습니다. 순환을 숨기는 응급처치일 뿐이고, 6개월 뒤엔 왜 거기 있는지 알 수 없게 됩니다.

데이터파트만 sw.decoding을 쓰는 이유는 실촬영 정답 번호를 디코더로 확보하기 때문입니다.

08

조심할 파일 하나

schemas.py는 두 파트가 주고받는 약속입니다. 한쪽이 말없이 바꾸면 반대쪽이 전부 깨집니다.

실패했는데 이유가 없는 상태는 금지입니다. 판독에 실패했으면 failure_reason이 반드시 있어야 객체가 만들어집니다.

파이프라인은 예외를 던지지 않습니다. 어떤 상황에서도 결과를 반환합니다 — 현장에서 예외가 올라오면 서비스가 멈추고, 그게 곧 노리드 존 정체입니다.

09

작업 흐름

브랜치를 만들고 PR을 올립니다. 검사 3개가 12초 안에 답을 줍니다.

git switch main
git pull
git switch -c ai/detection-baseline    # <파트>/<하는일>
# ... 작업 ...
uv run pytest                          # 올리기 전에 확인
git push -u origin ai/detection-baseline

규칙이지만 강제하지 않습니다. main에 직접 push가 되고, 승인이 없어도 머지 버튼이 눌리고, 빨간 X여도 머지됩니다. 장치로 막지 않기로 했으니 사람이 지켜야 합니다.

빨간 X는 혼내는 게 아닙니다. 뭐가 잘못됐는지 12초 안에 알려주는 장치입니다. 없으면 2주 뒤에 남이 발견하고, 그때는 원인 추적이 어렵습니다.

실패한 검사이렇게 고칩니다
ruffuv run ruff format . 다음 uv run ruff check --fix .
lint-imports부르면 안 되는 것을 불렀습니다. 필요해 보이면 설계가 잘못된 것이니 상의하세요
pytestuv run pytest -x로 첫 실패만 보면서 고치는 게 빠릅니다

일정 — 11월에 끝납니다

네 달입니다. 파트마다 바빠지는 달이 다릅니다.

달마다 무엇이 끝나야 하나

시기끝나야 하는 것
8월 완료 — 계약·테스트·CI가 서 있고 uv sync로 누구나 시작 가능
9월 데이터셋 v1, 탐지 모델 확정, 베이스라인 수치 확보
1주차에 바코드 종류·디코더를 정해야 나머지가 움직입니다
10월 복원 모델 확정, 3단계가 하나로 이어져 동작, 전체 지연 측정 완료
11월 시연 프로그램, 평가 보고서, 발표 자료
평가용 데이터는 2주차에 한 번만 씁니다 — 여러 번 보면 수치가 부풀려집니다

11월이 가장 위험합니다. 시연·평가·보고서가 한 달에 몰려 있습니다. 그래서 10월까지 "동작하는 상태"를 만들어두는 것이 중요합니다 — 11월에 기능을 새로 만들 여유는 없습니다.

Hugging Face 토큰 — 필요한 사람만

데이터와 가중치는 저장소에 올리지 않고 Hugging Face에 둡니다. 받기만 하는 사람은 토큰이 필요 없습니다. 올리는 사람만 발급하면 됩니다.

uv run hf auth login     # 붙여넣을 때 화면에 안 보이는 게 정상
uv run hf auth whoami    # 계정명이 나오면 성공

.env에 적어도 읽히지 않습니다 — 저장소에 .env를 읽는 코드가 없습니다. 옛 명령 huggingface-cli는 폐기됐으니 인터넷에서 본 명령은 hf로 바꿔 읽으세요.
